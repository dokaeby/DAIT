# Claude Code 전용 지침
위 AGENTS.md의 모든 절대원칙이 그대로 적용된다. 아래는 Claude Code에서만 추가로 지키는 내용이다.

1. 설계 요약 단계(작업 방식 1번)에서는 plan 모드를 사용하고, 승인 전에는 파일을 수정하지 않는다.
2. 코드 수정 후 AGENTS.md 10절의 품질 게이트(`ruff check`, `ruff format --check`, `pyright`, `pytest`)를
   직접 실행하고, 실제 출력 결과를 근거로 보고한다. 실행하지 못했다면 못 했다고 명시한다.
3. 인증, 세션, 크롤러의 SSRF 방어, 비밀값 처리 코드를 바꿀 때는 변경 전에 계획을 먼저 보여주고 승인을 받는다.
4. 다음 명령은 실행하지 않는다: `git push`, `git reset --hard`, `git clean -f`, `git branch -D`,
   `rm -rf`, `sudo`, `curl ... | sh`. 필요하면 명령을 제안만 하고 사용자가 직접 실행하게 한다.
5. `.env`, 키 파일, 인증서 등 비밀값 파일은 읽거나 출력하지 않는다. 필요한 환경변수 이름만 `.env.example`에 추가한다.
6. 한 번에 수정하는 파일은 가능한 한 적게 유지하고, 변경한 파일 목록과 이유를 마지막에 요약한다.
7. 새 모듈·파일을 추가하는 작업은 설계 요약에 "파일별 소속 계층"과 "허용되는 import 방향"(AGENTS.md 9절)을 포함한다.
   폴더를 만들거나 옮기거나 지우는 구조 변경은 plan 모드에서 승인을 받은 뒤에 한다.
8. 리팩터링(파일 이동·이름 변경·분리)은 기능 변경과 한 작업에 섞지 않는다.
   동작을 바꾸지 않는 별도 단위로 하고, 전후의 `pytest` 결과를 비교해 보고한다.
9. 계층 의존 방향(AGENTS.md 9-2)을 어긴 import가 의심되면 추측하지 말고 `tests/test_architecture.py`
   실행 결과로 확인한다. 이 테스트가 아직 없으면 만들 것을 제안만 한다.
10. 새 수집기(collector)를 추가할 때는 `services/`를 건드리지 않았는지, fixture 기반 테스트가 있는지 확인하고 보고한다.
