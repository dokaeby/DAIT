## 3. 현재 적용된 테스트 정책 — 최종 확정 아님

- user1: 인공지능 / user2: 보안·클라우드 / user3: 반도체. 사용자와 관심사는 코드 상수입니다. 사용자 테이블·비밀번호 인증은 없습니다.
- 로그인 추천은 관심사 하나 이상 일치하는 기사 중 최신순 최대 10개입니다. 부족하면 다른 기사로 채우지 않습니다.
- 키워드 검색은 제목·원문 RSS 설명·저장된 해외 한국어 제목에 대한 부분 문자열 일치입니다. 공백으로 구분한 여러 단어는 모두 일치해야 합니다. 카테고리명이나 AI 요약문 자체는 검색 대상이 아닙니다.
- 로그인 중에는 관심사 조건 AND 검색어 조건입니다. 계정 전환 시 검색어를 유지하며, 로그아웃하면 검색어를 비우고 비로그인 최신 10개로 돌아갑니다.
- 검색어 `반도`에는 `반도체`도 일치합니다. 현재 검색은 형태소 단위 검색이 아닙니다.
- 요약·번역은 최신 저장 결과 한 건을 사용합니다. 입력 해시가 다르면 오래된 결과를 표시하지 않습니다. 최신 결과가 실패이면 과거 성공 결과로 자동 대체하지 않습니다.
- generated는 형식 검사 통과이지 사실 검증 완료가 아닙니다. reviewed=0 결과는 검토 전 테스트 결과로 표시합니다.
- 임베딩 모델: **Sentence Transformers / `BAAI/bge-m3` / CPU**. 임베딩에 Ollama는 사용하지 않습니다. 요약·번역은 별도로 Ollama `qwen3:4b`를 사용합니다.
- 임베딩 입력은 원문 제목·RSS 설명·유효한 해외 한국어 제목입니다. 현재 AI 요약은 추가하지 않습니다.
- 코사인 유사도 범위는 -1~1이며 확률·정확도 백분율이 아닙니다.
- 임베딩 후보 최소 코사인 유사도 0.35, 각 검색 후보 상위 20개, 동등 가중치 RRF `1/(60+순위)` 합산, 결과 최대 10개가 임시 기준입니다.
- 메인 검색은 **여전히 키워드 검색**입니다. 임베딩 검색과 점수 확인은 `/search-lab` 별도 화면에 있습니다. 혼합 순위는 최신순이 아닙니다.

기존 `real_articles.json`은 현재 디스크 목록에서 확인되지 않습니다. SQLite가 주 데이터입니다. 사용자가 앞선 단계에 대해 테스트 완료 또는 성공했다고 가정하고 진행하라고 했지만, 그 보고를 현재 DB에서 실제 AI 생성 성공을 확인한 것으로 바꾸어 기록하지 않습니다.

생성 작업을 다른 경로에서 실행했다면 그곳의 DB와 현재 앱이 읽는 DB 경로가 같은지도 확인해야 합니다.

## 5. 검증한 범위와 미검증 범위

**직접 확인한 것**

- 기사 50개 및 국내/해외 수량, 테이블과 저장된 요약 상태를 SQLite로 읽어 확인했습니다.
- 일부 기사 조회·검색 후보 SQL·테이블 저장/조회 SQL을 확인했습니다.
- `node ui_step2/test_live_search.cjs` 통과: 입력·삭제·초기화, 이전 응답 무시, 한글 조합 중 요청, 검색 버튼/Enter 요청.
- 유사도 HTML 안 JavaScript의 문법 검사를 통과했습니다.

**직접 확인하지 못한 것**

- 이 도구 환경에서는 `.venv`가 참조하는 원래 Python 실행 파일을 찾지 못했습니다. Python 테스트와 서버 실행을 직접 검증하지 못했습니다.
- Sentence Transformers 모델 다운로드·인코딩·실제 유사도 값·실제 브라우저 조작은 직접 확인하지 못했습니다.
- 요약·번역 품질도 현재 파일에서 성공 결과로 확인되지 않았습니다.

따라서 다음 담당자는 소스 구현 완료와 실행 검증 완료를 구분해야 합니다. 모델 출력이나 유사도 값을 임의의 예제로 채워 넣지 않습니다.

## 6. GitHub 업로드와 데이터 전달

현재 작업 폴더에서 `.git`은 확인되지 않았고 `git status`는 저장소가 아니라고 응답했습니다. GitHub 업로드는 사용자가 수행할 예정이며, 이 작업에서 원격 저장소 생성·커밋·업로드는 수행하지 않았습니다.

기존 `.gitignore`의 `*.db`, `*.txt` 때문에 설치 명세와 테스트 DB가 빠질 수 있어 아래처럼 보완했습니다.

- `.venv/`, `venv/`, `__pycache__/`, Python 캐시, `.env`, SQLite 저널 파일 제외.
- `requirements.txt`는 제외 규칙의 예외로 포함.
- 아래 네 개 프로젝트 DB는 생성되어 있으면 업로드에 포함되도록 예외 지정.

```text
ui_step1/real_articles.db
ui_step3/summary_tests.db
ui_step3/foreign_translations.db
ui_step4/search_index.db
```

현재 존재하는 것은 첫 두 DB입니다. 이미 Git에서 추적 중이던 파일에는 ignore 규칙이 소급 적용되지 않으므로 업로드 목록에서 `.venv`와 캐시가 빠졌는지 확인하세요. 보고서 `.txt`는 기본 제외합니다. 필요한 보고서는 별도로 전달할 수 있습니다.

진행 중인 색인·생성 작업이 끝난 뒤 서버를 종료하고 DB를 전달하세요. Hugging Face/Ollama 모델 파일은 GitHub 프로젝트에 포함하지 않고 다른 PC에서 다시 받거나 별도 모델 캐시로 전달합니다.

## 7. 다른 Windows PC에서 복원

1. GitHub에서 프로젝트를 내려받고 기사 DB가 있는지 확인합니다. 기존 `.venv`는 PC의 절대 경로를 포함하므로 복사해서 사용하지 않습니다.
2. Python을 설치하고 프로젝트 루트의 CMD에서 새 가상환경을 만듭니다. 현재 코드의 문법 기준은 Python 3.10 이상입니다. 기존 가상환경 설정에는 Python 3.13.9가 기록되어 있습니다.

```cmd
py -m venv .venv
.venv\Scripts\activate.bat
python -m pip install -r ui_step4\requirements.txt
python ui_step2\app.py
```

3. 브라우저에서 http://127.0.0.1:8000/ 에 접속합니다. `.html` 파일을 더블클릭하는 방식이 아니라 Python 서버 주소로 접속해야 DB/API 기능이 동작합니다.
4. http://127.0.0.1:8000/search-lab 에서 **색인 준비·갱신 → 검색어 입력 → 유사도 비교**를 진행합니다. 모델 다운로드·진행·오류와 결과는 화면에서 확인합니다.
5. 모델과 패키지를 교체했다면 서버를 재시작하고 색인을 갱신합니다. 라이브러리·모델 버전·입력 해시가 다르면 기존 색인을 재사용하지 않습니다.

Sentence Transformers의 기본 모델 다운로드는 첫 실행 때 이루어집니다. 서버는 같은 실행 동안 모델을 메모리에 재사용합니다. 색인·비교 작업은 한 번에 하나만 실행합니다. 진행 중 작업과 비교 결과는 서버 메모리에 있으므로 재시작하면 사라지지만 완료된 기사별 색인은 DB에 남습니다.

기존 요약 DB를 화면에서 읽을 때 Ollama가 실행 중일 필요는 없습니다. 새로운 요약·번역을 만들려면 별도로 Ollama와 qwen3:4b가 필요합니다. 요약·번역 생성 자체는 아직 `ui_step3` 명령 기반이므로, 이를 추가 테스트할 때는 사용자 선호에 따라 브라우저 제어·진행 화면을 먼저 연결해야 합니다.

## 8. 다음 진행 순서

1. **최우선: 새 PC에서 HTML 유사도 화면 실제 실행 확인.** 현재 색인 DB가 없으므로 색인을 준비하고 기사별 코사인 값이 숫자로 표시되는지 확인합니다. 설치·모델 로드 오류가 나면 그 단계부터 해결합니다.
2. 같은 검색어로 키워드/의미/혼합 결과를 비교하고 관련 없는 결과, 검색 누락, CPU 응답 시간을 기록합니다. 0.35 임계값과 RRF 설정을 검토합니다.
3. 메인 검색에 키워드/혼합 모드 선택을 넣을지 결정합니다. 현재 메인에는 임베딩 모드가 없습니다. 입력마다 즉시 갱신하는 요구를 유지하면서 임베딩 계산 비용을 어떻게 다룰지 확인해야 합니다.
4. 요약·번역 성공 결과의 실제 생성·품질을 확인합니다. 현재 확인 가능한 상태는 실패/미생성입니다. 향후 테스트는 브라우저에서 생성·진행·실패를 확인할 수 있도록 연결합니다.
5. 세 화면 통합 회귀 확인: 비로그인 최신 10개 → 사용자별 추천 → 계정 전환 → 로그아웃 복귀 → 기사 팝업 → AI 상태·출처 링크 → 검색 입력/삭제/초기화.
6. 실제로 동작한 모델 커밋·패키지 버전과 테스트 결과를 문서에 반영합니다.

이후 별도 검토: 자동 카테고리 태그 개선, 원문 확보와 표시 범위 검토, 전문 기반 요약/해외 상세 번역, 추천 기사 수·관심사 부족 시 정책 확정. 현재 RSS 정보가 부족한 상태에서 AI로 내용을 만들어 채우지 않습니다.
