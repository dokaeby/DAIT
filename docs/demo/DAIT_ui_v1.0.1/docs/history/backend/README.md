# FastAPI 전환 1차 · 테스트 로그인

## 4단계 · 사용자별 관심 카테고리

### 로그인 직후 안내와 자유로운 화면 이동

카테고리를 저장하지 않은 회원은 로그인 직후 `/interests` 안내를 한 번 봅니다. 안내 화면에서 DAIT 로고·AI 뉴스 큐레이션 서비스·오늘의 AI 뉴스·AI·기술을 눌러 자유롭게 이동할 수 있고, ‘다음에 하기’로도 기본 메인에 이동합니다. 메인 접근 시 선택창으로 강제 복귀시키지 않습니다. 미설정 회원이 로그아웃 후 다시 로그인하면 선택창을 다시 안내하고, 저장한 회원은 바로 맞춤 메인으로 이동합니다. 미설정 회원은 전체 최신 뉴스·전체 범위 검색을 이용할 수 있습니다. 메인의 관심 카테고리 설정/변경에서 언제든 선택을 수정할 수 있으며, 저장 자체는 최소 한 개 선택 규칙을 유지합니다. 이 변경의 실행 테스트는 사용자 확인을 기다립니다.

안내 여부는 현재 저장된 카테고리로 판단합니다. 이전 버전의 빈 건너뛰기 프로필이 있어도 미설정이면 다음 로그인 때 안내합니다. 건너뛰기 API는 이제 완료 기록을 저장하지 않으며 기존 관심사나 회원 데이터도 삭제하지 않습니다. 기존 테스트 계정의 기본 관심사 또는 사용자가 저장한 관심사는 설정된 것으로 판단합니다.

3단계 DB 로그인은 사용자가 실행하여 정상 작동을 확인했습니다. 이번 단계에서는 사용자별 관심 카테고리 선택·DB 저장·맞춤 메인·검색 범위를 연결했습니다. 실행 테스트는 사용자 확인을 기다립니다.

### 화면과 동작

- 미설정 회원은 로그인 직후 안내를 보되 언제든 다른 메뉴로 이동할 수 있습니다. 미설정 상태로 다시 로그인하면 안내를 다시 보고, 설정한 회원은 바로 메인으로 갑니다.
- 제공하는 카테고리는 기사 DB의 현재 `article_categories` 목록입니다. 한 개 이상을 여러 개 선택할 수 있고 전체 선택·선택 해제를 제공합니다.
- 저장이 완료되면 맞춤 메인으로 이동합니다. 메인의 ‘관심 카테고리 변경’ 또는 좌측 ‘관심 카테고리’에서 다시 수정할 수 있습니다.
- 맞춤 뉴스는 선택한 카테고리 중 하나 이상이 일치하는 기사를 최신순으로 최대 10개 표시합니다. 부족하다고 다른 분야의 기사로 채우지 않습니다.
- 로그인 상태의 키워드 검색과 임베딩 검색에도 같은 관심사 범위를 적용합니다. 메인의 카테고리 필터에는 선택한 관심 카테고리가 나타납니다.
- user1~3은 아직 저장한 선택이 없다면 기존 관심사를 초기값으로 사용합니다. 변경 저장한 뒤에는 해당 계정의 DB 선택을 사용하며, 다른 계정에는 반영되지 않습니다.
- 게스트의 `/interests` 접근은 메인으로 이동하고 API 조회·저장은 로그인 없이 사용할 수 없습니다.

### 데이터와 팀 코드 연결

서버 시작 시 기존 회원 DB에 `interest_profiles`와 `interest_categories` 테이블을 추가합니다. 기존 회원·비밀번호·세션은 유지합니다. 프로필은 회원 번호 또는 테스트 계정에 연결되며 다른 사용자 아이디를 요청에 넣어 수정할 수 없습니다.

- `GET /api/interests`: 현재 사용자의 제공 목록과 선택 목록 조회.
- `PUT /api/interests`: JSON `{"categories": ["보안", "클라우드"]}`로 본인의 선택 저장.
- `GET /api/auth/me`: 현재 계정과 저장된 관심사 조회.

위 API는 이후 팀원의 설정 화면에서도 재사용할 수 있습니다. 현재 설정 화면의 예약·알림·노출 수 등은 여전히 미저장 미리보기이며, 이번 실제 저장은 전용 관심 카테고리 화면에만 연결했습니다.

검색 작업에는 시작 시점의 관심사 목록을 전달합니다. 관심사 변경 전 작업 결과를 다른 범위의 결과로 표시하지 않도록 결과를 불러올 때 현재 선택과 비교합니다. 카테고리 변경 자체로 기사 임베딩을 다시 만들지는 않습니다.

### 직접 확인할 순서

추가 패키지는 없습니다. 기존 FastAPI 서버를 종료하고 재시작한 뒤 Ctrl+F5로 새로고침합니다.

1. 미설정 회원으로 로그인해 안내를 확인한 뒤 로고·서비스명·오늘의 AI 뉴스·AI·기술로 자유롭게 이동하는지 확인합니다. ‘다음에 하기’도 기본 메인으로 이동해야 합니다. 미설정 상태에서 로그아웃·재로그인하면 다시 안내하며, 카테고리를 저장한 뒤에는 재로그인 시 바로 메인으로 이동해야 합니다.
2. 아무것도 선택하지 않고 저장하면 안내가 나오는지 확인합니다.
3. 보안·클라우드 등 원하는 항목을 선택·저장한 뒤 맞춤 목록과 상단 관심사가 일치하는지 확인합니다.
4. 관심 카테고리를 변경해 추천 목록과 검색 범위가 함께 바뀌는지 확인합니다. 기사에 여러 태그가 있다면 선택한 것 중 하나 이상이 일치하면 포함됩니다.
5. 다른 계정으로 전환하여 선택이 섞이지 않는지 확인합니다. user1~3의 관심사도 변경해 볼 수 있습니다.
6. 로그아웃·재로그인과 서버 재시작 후 선택이 유지되는지 확인합니다.
7. 게스트 모드에서 선택 화면과 API의 접근 제한을 확인합니다.
8. `/settings`의 관심 키워드 초기값에도 저장한 카테고리가 표시되는지 확인합니다. 해당 설정 폼은 여전히 화면 미리보기입니다.

이번 단계는 서버·자동 테스트·브라우저 테스트를 실행하지 않았습니다. 코드 반영 작업에 회원 DB 파일을 포함하지 않으며, 새 테이블은 사용자가 서버를 다음에 시작할 때 추가됩니다.

## 3단계 · DB 회원 로그인과 세션

2단계 회원가입 저장은 사용자가 실행하여 정상 작동을 확인했습니다. 3단계는 DB 회원의 Argon2 비밀번호 검증, 서버 세션 발급·조회·폐기와 기존 화면 연결을 구현한 상태이며 사용자의 실행 확인을 기다립니다.

- 신규 회원은 2단계에서 가입한 아이디·비밀번호로 로그인할 수 있도록 연결했습니다.
- 아이디 중복 검사와 같은 정규화 기준으로 로그인 계정을 찾습니다. 응답에는 저장된 아이디 표기를 사용합니다.
- `dait_session` 쿠키에는 무작위 세션 토큰을 넣고, DB `sessions` 테이블에는 토큰의 SHA-256 해시와 회원 번호·만료 시각만 저장합니다. 테스트 계정 호환 세션은 테스트 계정명을 별도 열에 저장합니다.
- 세션 유효 기간은 24시간입니다. DB 세션과 쿠키가 유지되는 동안 새로고침·서버 재시작 후에도 로그인 상태를 확인합니다.
- 쿠키는 HttpOnly·SameSite=Lax·Path=/입니다. HTTPS 요청에서는 Secure도 적용합니다.
- 로그아웃하면 서버의 현재 세션과 쿠키를 제거합니다. 계정 전환은 새 토큰을 발급하고 이전 세션을 폐기합니다. 다른 브라우저의 세션은 유지합니다.
- 같은 계정에 다시 로그인하면 기존대로 ‘이미 로그인되어 있습니다.’를 표시하고 팝업을 유지합니다.
- 이전 `dait_user` 계정명 쿠키는 FastAPI 인증에 사용하지 않습니다. 이 버전으로 전환한 뒤에는 한 번 다시 로그인해야 합니다.
- user1/user2/user3의 1234 테스트 로그인은 호환 기능으로 유지하며, 이 계정들도 새 세션을 사용합니다.
- 신규 회원의 카테고리 선택과 맞춤 뉴스는 위 4단계에서 연결했습니다. 이 문단 아래는 3단계 당시의 구현·확인 기록입니다.

기존 회원 데이터는 지우지 않습니다. 서버를 시작할 때 기존 DB에 필요한 세션 테이블을 추가합니다. 이번 코드 작성 중에는 서버를 실행하거나 DB를 변경하지 않았습니다.

현재 실제 프로젝트 경로는 `C:\DAIT_test\DAIT_ui`입니다. 해당 경로에서 실행합니다.

```powershell
cd C:\DAIT_test\DAIT_ui
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

직접 확인할 순서:

1. 기존 서버를 종료 후 재시작하고 Ctrl+F5로 갱신합니다.
2. 2단계에서 가입한 계정의 잘못된 비밀번호로 로그인해 실패·팝업 유지를 확인합니다.
3. 올바른 비밀번호로 로그인하고 헤더의 아이디와 `/api/auth/me`의 logged_in=true를 확인합니다. 신규 계정은 interests=[]가 정상입니다.
4. 같은 계정으로 다시 로그인해 안내·팝업 유지를 확인합니다.
5. 다른 신규 계정이나 user1~3으로 전환해 현재 계정이 변경되는지 확인합니다.
6. 새로고침과 서버 재시작 후 같은 브라우저에서 로그인 상태가 유지되는지 확인합니다.
7. 로그아웃 후 `/api/auth/me`의 logged_in=false와 `/settings`의 접근 차단을 확인합니다.
8. 기존 테스트 계정의 맞춤 메인·검색, 로그인/계정 전환 시 검색어 초기화·유지 규칙을 확인합니다.

이번 3단계는 의존성 설치·서버 실행·자동 테스트·브라우저 테스트를 수행하지 않았습니다. 다음 단계는 사용자 확인 후 진행합니다.

## 회원가입 전환 · 1단계 화면

로그인 팝업의 테스트 계정 안내를 제거하고 제출 버튼을 ‘확인’으로 변경했습니다. ‘회원가입’을 누르면 같은 팝업에서 아이디·비밀번호·비밀번호 확인 화면으로 전환하며, ‘로그인으로 돌아가기’로 복귀합니다. 닫기·Esc 후 다시 열면 로그인 화면으로 시작합니다.

회원가입 비밀번호와 확인 입력의 5자 미만 안내, 두 값 불일치 안내는 사용자가 적용을 확인했습니다. 이어서 아래 2단계의 서버 검증·회원 DB 저장을 연결했습니다. 기존 테스트 로그인은 유지합니다.

확인 순서: 로그인 팝업의 문구·확인 버튼 → 회원가입 화면 전환 → 로그인 화면 복귀 → 닫기·Esc와 다시 열기 → 기존 로그인 성공·실패·동일 계정 안내 유지.

## 회원가입 · 2단계 DB 저장

`POST /signup`에서 Pydantic으로 입력을 검증하고 `backend/data/users.db`의 `users` 테이블에 저장합니다. DB는 현재 서버 시작 시 준비하며 기존 데이터는 유지합니다. 기사 DB는 재사용하지 않습니다.

- 아이디는 공백 없는 1~30자입니다. 대소문자와 유니코드 호환 표기를 정규화한 비교 키로 중복을 확인합니다.
- 기존 테스트 계정 user1/user2/user3은 예약된 아이디로 취급합니다.
- 비밀번호와 확인 입력은 5~128자이며 두 값이 일치해야 합니다. 비밀번호는 Argon2 해시로 저장하며 확인 입력은 저장하지 않습니다.
- 저장 항목은 회원 번호, 아이디, 중복 비교 키, 비밀번호 해시, 가입 시각입니다. 비밀번호 원문·해시는 API 응답에 포함하지 않습니다.
- DB의 UNIQUE 제약으로 동시 가입 중복도 방지합니다. 성공은 201, 중복은 409, 입력 오류는 422 응답입니다.
- 회원 DB는 기존 `*.db` 제외 규칙에 따라 Git 추적에서 제외됩니다.

새 의존성을 설치하고 FastAPI 서버를 다시 시작합니다.

```powershell
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

브라우저에서 Ctrl+F5로 갱신한 뒤 다음을 확인합니다.

1. 새 아이디와 같은 5자 이상 비밀번호로 가입하면 저장 완료 안내가 표시되는지 확인합니다.
2. 같은 아이디로 다시 가입하면 아이디 아래에 중복 안내가 표시되는지 확인합니다.
3. 대소문자만 바꾼 아이디, user1/user2/user3도 중복으로 처리되는지 확인합니다.
4. 5자 미만·비밀번호 불일치·공백 포함 아이디가 거부되는지 확인합니다.
5. 서버 재시작 후 같은 아이디가 계속 중복으로 처리되면 저장이 유지된 것입니다.

2단계의 범위는 회원가입 저장까지였으며 사용자가 확인했습니다. 새 회원의 로그인·세션은 위 3단계에서 연결했고, 관심 카테고리는 4단계입니다.

사용자 요청에 따라 의존성 설치·서버 실행·회원 데이터 생성·테스트는 수행하지 않았습니다. 이번 단계의 실행 검증은 미완료입니다.

## 설정 화면 진입 · 1단계 추가

로그인한 사용자에게만 헤더·사이드바·모바일 탐색에 `/settings` 링크가 표시됩니다. 게스트가 주소를 직접 열면 메인으로 돌아갑니다. 이 진입 단계는 사용자가 실행하여 정상 작동을 확인했습니다.

### 설정 화면 구성 · 2단계

화면설계서 6번 슬라이드에 맞춰 예약 수집, 관심 설정, 노출·알림, 계정·정책을 구성했습니다. 기본 예약 예시는 08:30 KST, 기본 노출 수는 10개(5개 선택 가능), 인앱 알림 켜짐·메일 알림 꺼짐입니다. 키워드는 현재 계정의 관심사에서 시작합니다.

이번 단계는 화면 확인 범위입니다. 입력과 토글은 화면에서만 바뀌며, 저장·실제 예약·추천 변경·알림 전송·탈퇴는 아직 연결하지 않았습니다. 설정 저장 버튼에는 미저장 안내가 표시되고, 변경 취소는 초기값으로 복원합니다. 개인정보·탈퇴 안내는 별도 팝업입니다.

이번 화면 구성의 실행 테스트는 아직 수행하지 않았습니다. 사용자가 다음을 직접 확인한 뒤 실제 저장 등 다음 단계를 진행합니다.

1. 예약 수집·관심 설정·노출·알림·계정·정책 화면과 구역 이동.
2. 예약 시각과 토글 변경, 키워드 최대 3개 입력·미리보기, 노출 수 선택.
3. 변경 취소 후 초기값 복원, 설정 저장 시 미저장 안내.
4. 개인정보 처리 안내·탈퇴 안내 팝업 열기와 닫기·Esc.
5. 새로고침하면 변경값이 초기화되고, 실제 맞춤 뉴스는 바뀌지 않는지 확인.
6. 모바일에서 구역 메뉴·입력·토글·버튼 배치 확인.

기존 화면의 테스트 로그인을 FastAPI 라우터로 옮긴 단계입니다. 계정 정보는 기존 `ui_step2/app.py`의 테스트 설정을 참조합니다. 회원 DB·비밀번호 해시·세션 인증·이메일 인증은 아직 구현하지 않았습니다.

## 설치와 실행

기존 `python ui_step2/app.py` 서버가 실행 중이라면 Ctrl+C로 종료합니다. PowerShell에서 프로젝트 루트로 이동한 뒤 실행합니다.

```powershell
cd C:\DAIT_test\DAIT_ui
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

화면: http://127.0.0.1:8000/

API 문서: http://127.0.0.1:8000/docs

로그인 상태: http://127.0.0.1:8000/api/auth/me

이번 단계의 새 진입점은 `backend.main:app`입니다. 기존 진입점은 보존되어 있으며, `python ui_step2/app.py`로 실행하면 이전 표준 HTTP 서버가 실행됩니다. 두 서버를 같은 포트로 동시에 실행하지 않습니다.

AI 검색·요약 작업 상태와 모델은 현재 프로세스 메모리에 있습니다. 이 단계에서는 worker 1개를 사용하고 `--reload`와 `--workers` 옵션은 추가하지 않습니다. Redis 공유 작업 관리는 다음 단계입니다. 모델은 실제 검색·생성 요청이 있을 때 로드합니다.

## 그대로 옮긴 로그인 규칙

| 상황 | 동작 |
|---|---|
| user1 / 1234 | 인공지능 맞춤 메인 |
| user2 / 1234 | 보안·클라우드 맞춤 메인 |
| user3 / 1234 | 반도체 맞춤 메인 |
| 잘못된 계정·비밀번호 | 401, 팝업 안에 오류 표시 |
| 현재 계정으로 다시 로그인 | 409, ‘이미 로그인되어 있습니다.’ 표시, 팝업 유지 |
| 비로그인 → 로그인 | 검색어 초기화 |
| 로그인한 계정끼리 전환 | 검색어 유지 |
| 로그아웃 | 쿠키 제거, 비로그인 기본 메인 복귀 |
| 누락·과도한 길이 등 잘못된 입력 | Pydantic 검증, 422, 팝업 안내 |

현재는 위 3단계의 `dait_session` 검증을 사용합니다. 이전 `dait_user` 테스트 쿠키는 로그인 근거로 사용하지 않습니다. API 상태 응답에는 로그인 여부·계정·관심사만 포함하며, 검증 오류에 비밀번호 입력을 다시 내보내지 않습니다.

## 코드 구성

- `main.py`: FastAPI 앱, 라우터 등록, 공통 오류·캐시 응답 처리.
- `auth.py`: 로그인·로그아웃·현재 로그인 상태 라우터.
- `schemas.py`: 로그인 폼, 상태 응답 및 기존 요청의 Pydantic 모델.
- `legacy.py`: 기존 함수를 서버 실행 없이 불러오는 연결부.
- `compatibility.py`: 기존 화면·정적 파일·기사·검색·요약의 HTTP 연결부. 실제 조회와 AI 처리 함수는 재사용합니다.

로그인 팝업에서 성공 후 이동하는 메인과 기존 화면의 API가 끊기지 않도록 연결부를 함께 구성했습니다. 검색·요약의 계산 방식, DB와 화면 디자인은 이 단계의 변경 대상이 아닙니다.

## 직접 확인할 순서

1. 서버 실행 후 브라우저에서 Ctrl+F5로 새로고침하고 메인 화면이 열리는지 확인합니다.
2. 로그인 팝업에서 잘못된 비밀번호로 실패 메시지가 표시되고 창이 유지되는지 확인합니다.
3. user1 / 1234로 로그인하고 맞춤 뉴스 및 `/api/auth/me`의 계정·관심사를 확인합니다.
4. 계정 전환 창에서 user1 / 1234를 다시 입력하고 ‘이미 로그인되어 있습니다.’와 팝업 유지를 확인합니다.
5. user2, user3으로 계정을 바꾸고 각 관심사 목록을 확인합니다.
6. 비로그인에서 검색 후 로그인하면 검색어가 지워지는지, 로그인 계정 간 전환에서는 검색어가 유지되는지 확인합니다.
7. 로그아웃 후 비로그인 메인과 `/api/auth/me`의 logged_in=false를 확인합니다.
8. 기사 팝업, 카테고리 필터, 검색 유사도 등 기존 기능이 유지되는지 확인합니다.

사용자 요청에 따라 의존성 설치, 서버 실행, 자동 테스트와 브라우저 검증은 수행하지 않았습니다. 이번 단계의 실행 성공을 확인한 기록은 아직 없습니다.
