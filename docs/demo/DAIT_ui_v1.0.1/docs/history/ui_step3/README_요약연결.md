# 6단계: 저장된 요약을 상세 팝업에 연결

실행 중인 화면 서버를 종료한 뒤, 프로젝트 폴더에서 다시 실행하세요.

```cmd
.venv\Scripts\python.exe ui_step2\app.py
```

http://127.0.0.1:8000 에서 기사를 클릭하면 AI 3줄 요약, 기존 RSS 설명, 출처 링크를 볼 수 있습니다. 요약을 이미 저장했다면 화면을 볼 때 Ollama가 실행 중일 필요는 없습니다.

기사 ID로 `ui_step3/summary_tests.db`를 조회하며, 해당 기사의 가장 나중에 저장된 결과 한 건을 사용합니다. 최신 결과가 실패이면 이전 성공 결과를 대신 표시하지 않습니다. 현재 제목과 RSS 설명이 요약 생성 당시 입력과 달라졌으면 재생성이 필요하다고 안내합니다. 입력 일치 여부는 해시로 비교합니다.

## 결과별 표시

| 상태 | 표시 |
|---|---|
| generated | 요약 세 항목과 RSS 기반 AI 요약 안내 |
| missing | 아직 생성되지 않은 기사 안내 |
| insufficient | 입력 정보 부족 안내 |
| error | 요약 생성 실패 안내 |
| stale | 기사 정보 변경으로 재생성 필요 안내 |
| invalid / unavailable | 형식 오류 또는 요약 조회 불가 안내 |

샘플 생성기는 reviewed=0으로 저장하므로 생성 결과에는 검토 전 테스트 결과라는 안내가 붙습니다. 기사 설명과 요약은 별도 영역이며 RSS 설명을 AI 요약으로 대신 표시하지 않습니다.

## 직접 확인할 내용

1. 샘플 보고서의 기사 제목을 목록에서 찾아 클릭하고 요약 세 항목이 보고서와 같은지 확인합니다. 최신 10개 목록에 없으면 보고서의 기사 ID로 `/article/기사ID` 주소에 직접 접속할 수도 있습니다.
2. 요약을 생성하지 않은 기사도 클릭해 미생성 안내가 나오는지 확인합니다.
3. 다른 기사를 연속으로 열고 닫아 이전 요약이 남지 않는지 확인합니다.
4. 사용자 전환과 로그아웃 뒤에도 기사와 요약이 정확히 연결되는지, 원문 링크가 맞는지 확인합니다.

연결 당시 기존 결과 DB에는 error 기록만 있었습니다. 생성 성공 결과를 확인하려면 Ollama를 실행하고 모델을 내려받은 뒤 다음 명령을 실행하세요.

```cmd
.venv\Scripts\python.exe ui_step3\test_summaries.py
```

생성 후 팝업을 닫았다가 다시 열면 새 결과를 조회합니다. 두 DB는 화면에서 읽기만 하며 접속 시 요약을 새로 생성하지 않습니다.

연결 로직 자동 점검:

```cmd
.venv\Scripts\python.exe -m unittest discover -s ui_step2 -p test_ai_summary.py
```

자동 점검은 별도 임시 DB를 사용합니다. 실제 AI 품질이나 브라우저 팝업 동작까지 검증하는 테스트는 아닙니다.
