# 7단계: 국내 기사 전체 요약

기존 샘플 요약과 같은 로컬 모델·RSS 입력 방식을 국내 기사 전체로 확대합니다. 해외 기사는 이 단계에서 처리하지 않습니다. 작업 당시 DB에는 국내 48개, 해외 2개가 있습니다. 기사 수는 재수집 결과에 따라 달라집니다.

가상환경이 활성화된 CMD에서 프로젝트 폴더를 기준으로 실행하세요.

```cmd
python ui_step3\summarize_domestic.py --status
python ui_step3\summarize_domestic.py --list
```

위 명령은 AI 요청이나 파일 변경 없이 현재 요약 상태와 처리할 기사를 확인합니다. 생성하려면 Ollama와 qwen3:4b 모델이 준비된 상태에서 다음 명령을 실행하세요.

```cmd
python ui_step3\summarize_domestic.py
```

Ollama 연결과 모델 설치를 먼저 확인하며 실패하면 기사 처리를 시작하지 않습니다. 로컬에서 순차 생성하므로 전체 처리에는 시간이 걸릴 수 있습니다. 기사별 기본 대기 제한은 600초이며 `--timeout 900`처럼 변경할 수 있습니다.

## 재실행과 중단

- 같은 모델과 같은 입력의 최신 결과가 정상 3줄 요약이면 재사용합니다.
- 같은 조건에서 정보 부족으로 처리된 기사도 재사용합니다. 입력이 그대로인 상태에서 재시도하려면 `--force`를 사용합니다. 이 옵션은 성공 결과도 재생성하므로 필요한 경우에만 사용하세요.
- 미생성·실패·요약 형식 오류·입력 변경·모델 변경 기사는 다시 처리합니다.
- RSS 설명이 비어 있으면 모델을 호출하지 않고 정보 부족으로 기록합니다.
- Ctrl+C로 중단해도 완료된 기사별 결과는 DB에 남습니다. 같은 명령으로 재실행하면 재사용 가능한 기사는 건너뜁니다.
- 실행 도중 연결 오류가 생기면 해당 오류를 기록하고 중단합니다. Ollama 상태를 해결한 뒤 다시 실행하세요.

기존 `summary_tests.db`에 실행별 기록을 추가하고 `domestic_report_실행ID.txt`에 입력과 결과를 저장합니다. 기사 원본 DB는 읽기만 합니다. 팝업은 이미 이 요약 DB와 연결되어 있어 다시 열면 최신 저장 결과를 표시합니다. 성공 결과도 검토 전 테스트 결과로 저장하며 자동으로 검토 완료 처리하지 않습니다.

## 확인 순서

1. 실행 후 `--status`로 generated, insufficient, error 등 상태별 기사 수를 확인합니다. 48개 모두 성공한다고 가정하지 않습니다.
2. 새 보고서에서 여러 기사의 원래 입력과 요약을 비교합니다.
3. 화면 서버를 실행하고 각 사용자 추천 목록의 기사 팝업에서 요약이 연결되는지 확인합니다.
4. 같은 명령을 다시 실행해 성공·정보 부족 결과가 재사용되는지 확인합니다.

이번 단계는 RSS 설명을 바탕으로 한 요약입니다. 기사 전문 수집, 해외 번역, 검색 기능은 별도 단계입니다.

재사용 조건 자동 점검은 임시 DB만 사용합니다.

```cmd
python -m unittest discover -s ui_step3 -p test_domestic.py
```
