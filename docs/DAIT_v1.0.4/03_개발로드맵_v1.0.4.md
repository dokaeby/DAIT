## 1. 로드맵 원칙

1. 보안·데이터 무결성·검증을 기능 완료와 같은 우선순위로 둔다.
2. 단계 1에서 메인·상세보기·설정을 완성하고, 소셜 로그인·MFA·다중 카테고리는 MVP 검증 후 시작한다.
3. API·DB·Redis·화면을 마지막 날 한 번에 합치지 않고 작은 수직 단위로 매일 통합한다.
4. 외부 서비스는 첫 주에 기술 검증하고 실패 가능한 대체 경로를 정한다.
5. 각 작업은 정상·실패 예시와 자동 검사를 포함할 때 완료다.
6. 현재 단계에서 만들지 않는 기능은 문서로만 남기고 버튼·테이블·추상화를 선구현하지 않는다.

실명은 단계 0에서 채운다. 모든 핵심 영역은 최소 한 명의 백업이 실행 방법과 테스트를 확인한다.

## 8. 작업 완료 기준

작업 카드는 다음을 모두 포함해야 완료다.

- 연결된 기능 ID와 합격 기준 ID
- 구현 파일과 API·스키마 변경 내용
- 정상·경계·차단되어야 하는 테스트
- release 모드에 미치는 영향
- 사용자 화면 또는 API의 실제 관찰 결과
- 관련 문서와 결정 기록 갱신
