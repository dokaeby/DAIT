## 0.1 v1.0.1 화면 반영 사항

- 화면 기준은 `DAIT_화면설계서_v1.0.4.pptx`를 따른다.
- 메인 화면은 통합 검색, `전체`/`AI·기술` 필터, `랭킹순`/`최신순` 정렬, 랭킹 카드, 처리 상태, `원문 열기`, `링크 복사`를 포함한다. (`상세 보기` 행동은 1.0.4.1에서 제거)
- 뉴스 상세는 화면으로 제공하지 않는다(1.0.4.1). `GET /v1/news/{news_id}` 상세 API 계약(기사 헤더 정보, AI 3줄 요약, 번역, 처리 정보, 원본 정보, 관련 뉴스)은 유지하되 UI는 카드의 원문 새 탭·링크 복사만 제공한다.
- 설정 화면은 단계 1 MVP 구현 화면이며 예약 수집, 관심 카테고리, 닉네임 변경, 개인정보 처리 안내·회원탈퇴를 실제 저장·조회 동작과 연결한다. `노출·알림` 섹션(기본 노출 수·관심 키워드·인앱/메일 알림 토글)은 화면에서 제공하지 않는다(1.0.4.1 — 관련 설정 API 필드·DB는 유지).
- 정적 목업의 입력·토글·저장·원문·링크 복사 버튼은 화면 확인용이며 실제 동작 계약은 본 문서의 API/브라우저 동작 규칙을 따른다.

## 0.2 v1.0.3 구현 반영 사항

- 인증은 Bearer 토큰 방식이다(쿠키 아님). 가입·로그인 응답의 `tokens`를 사용한다.
- 신규 구현 기능: `GET /v1/me/session`, `PATCH /v1/me/nickname`,
  `GET /v1/auth/nickname-availability`, `GET /v1/interests/catalog`,
  `GET`/`PUT /v1/me/interests`, `GET /v1/news/activity`, `PUT /v1/news/{id}/read`,
  `GET /v1/me/schedule-runs`, `POST /v1/me/schedule-runs/seen`.
- 카테고리는 `AI`/`ECONOMY`/`POLITICS` 3개가 활성이다(WEATHER는 Enum만 존재).
- 비로그인 뉴스 목록은 최신순·`page_size<=10`·cursor 불가의 제한 응답이다.
- 로그인 실패는 Redis 분산 스로틀(`rate:login:*`)이 적용된다.
- 예약 검색은 외부 cron tick → `schedule_runs` 생성 → `BackgroundTasks` 검색 →
  `schedule_run_items` 저장 흐름으로 실행된다.

## 0.3 v1.0.4 구현 반영 사항

- `GET /v1/news`에 `language=ko|en`, `topic`, `personalized`, `interest` 질의가 추가됐다.
  `personalized`/`interest`는 로그인 사용자 전용이며 저장 관심사 코드여야 한다.
- `GET /v1/news/activity`가 `personalized`/`language` 조건과 `interest_counts`를 지원하고,
  `GET /v1/news/read-state?ids=`가 읽음 ID만 별도 반환한다.
- 관심사는 `GET /v1/interests/catalog`·`GET`/`PUT /v1/me/interests`로 관리하며
  한국어 15개 + `en.*` 15개(최대 30개)다. 기사 매칭은 `interest_matching.KEYWORDS`의
  명시적 키워드 규칙(제목·요약 LIKE, 카테고리·언어 조건 결합)을 사용한다.
- 목록·관련 뉴스·랭킹 모두 `published_at DESC`가 최우선이다(품질·출처는 동률 보조).
- 로그인·탈퇴 잠금은 계정+IP(5회)·계정 전체(50회)·IP(20회) 3단계다.
- `pipeline_sync_service`가 목록 요청 시 5분 간격으로 `pipeline`→`public` 기사를
  동기화한다(PostgreSQL 전용, canonical_url 중복 제외).
- 수집 fetch는 검증한 공인 IP로 연결을 고정하고(DNS rebinding 방지), HTML은 선언된
  charset으로 디코딩한다. 영문 제목 번역 실패 시 LLM 백업 경로가 있다.
- `GET /v1/internal/keepalive`가 무의존 200 응답을 제공한다.

## 1. 공통 규칙

- `MVP`는 단계 1 구현 대상이다. 메인·설정 화면을 포함한다(상세보기 화면·노출·알림 메뉴는 1.0.4.1에서 제거, API는 유지). `단계 2`는 소셜 로그인·MFA 등 인증 확장 기능에 한정한다.
- 응답 시각은 UTC ISO 8601, 사용자 시간대는 IANA 이름으로 별도 저장한다.
- 외부에 노출하는 ID는 불투명 문자열이며 순차 ID를 권한 판단에 사용하지 않는다.
- 오류는 `code`, 일반화된 `message`, `request_id`, 선택적 `fields`로 반환한다.
- release 응답과 로그에 비밀번호, 토큰, 이메일 원문, 인증코드, 내부 예외를 노출하지 않는다.
- 사용자 소유 데이터는 인증 사용자 ID로 저장소 질의를 제한한다.
- 모든 쓰기 요청은 길이·형식·허용값 검증과 속도 제한을 적용한다.
- 접근성 상태 메시지는 `aria-live` 등 동등한 방법으로 전달하며 포커스를 잃지 않는다.

## 2. FR-AUTH-01 이메일 회원가입

| 항목 | 설계 |
|---|---|
| 단계 | MVP |
| 사용자 목표 | 이메일과 비밀번호로 안전하게 계정을 만들고 첫 화면으로 이동 |
| API | `POST /v1/auth/signup` |
| 데이터 | `users`, `refresh_sessions`, `audit_logs` |
| 합격 기준 | AC-AUTH-01, AC-AUTH-02 |

### 입력과 처리

- 입력: `email`, `password`, `password_confirm`, `terms_accepted`
- 이메일은 형식·길이를 검증하고 비교용 값만 정규화한다.
- 비밀번호는 최소 길이, 최대 길이, 유출 비밀번호 차단을 적용한다.
- 비밀번호 확인과 필수 약관 동의가 일치해야 한다.
- 비밀번호는 Argon2id 우선 또는 bcrypt로 해시하고 평문을 즉시 폐기한다.
- 사용자 생성과 최초 세션 생성은 하나의 트랜잭션 경계로 처리한다.

### 응답과 화면

- 성공: 201, 사용자 공개 정보와 세션 설정 후 AI 뉴스 첫 화면으로 이동
- 실패: 필드 오류는 해당 입력에 연결하되 이메일 존재 여부를 제3자가 확인할 수 없게 문구와
  응답 시간을 통제한다.
- 제출 중 버튼을 잠그고 중복 클릭으로 계정이 둘 생기지 않게 한다.

### 보안·검증

- IP와 이메일 해시 단위 속도 제한
- 비밀번호·해시·토큰 로그 금지
- 동시 가입은 DB unique 제약으로 최종 방어
- 테스트: 정상, 잘못된 이메일, 불일치, 약한·너무 긴 비밀번호, 중복, 동시 요청, 속도 제한

## 3. FR-AUTH-02 소셜 회원가입과 로그인

| 항목 | 설계 |
|---|---|
| 단계 | 단계 2 |
| 제공자 | Google, Kakao, Apple |
| API | `GET /v1/auth/oauth/{provider}/start`, callback |
| 데이터 | `users`, `auth_identities`, `refresh_sessions`, `audit_logs` |
| 합격 기준 | AC-AUTH-03 |

### 흐름

1. 허용 제공자인지 확인하고 state, nonce, PKCE verifier를 생성한다.
2. verifier와 state는 짧은 TTL로 서버 측 저장하고 고정 redirect URI를 사용한다.
3. callback에서 state, nonce, issuer, audience, 만료와 서명을 검증한다.
4. `(provider, provider_subject)`로 계정을 찾거나 새 사용자를 만든다.
5. 이메일이 같다는 이유만으로 서로 다른 제공자 계정을 자동 병합하지 않는다.

### 실패·보안

- 사용자 취소, 접근 거부, state 불일치, 제공자 오류, 네트워크 오류를 내부 코드로 구분한다.
- 화면 문구는 재시도 가능 여부를 알려주되 토큰·제공자 원문 오류를 노출하지 않는다.
- 계정 연결은 로그인 상태에서 재인증 후 별도 동의로 수행한다.
- 테스트: 제공자별 성공, 취소, 거부, 위조 state, 만료 code, 중복 subject, 동일 이메일 타 제공자

## 4. FR-AUTH-03 로그인과 로그아웃

| 항목 | 설계 |
|---|---|
| 단계 | MVP |
| API | `POST /v1/auth/login`, `/refresh`, `/logout` |
| 데이터 | `users`, `refresh_sessions`, `audit_logs` |
| 합격 기준 | AC-AUTH-04 |

### 로그인

- 이메일·비밀번호를 검증하고 계정 상태를 확인한다.
- 실패 응답은 계정 없음·비밀번호 오류·잠김 여부를 구분하지 않는다.
- 로그인 잠금은 3단계다(v1.0.4): 계정+접속 IP 5회, 계정 전체 50회(분산 대입 완화),
  IP 20회. 탈퇴(`DELETE /v1/me`)도 같은 잠금 장치를 공유한다.
- 액세스 토큰은 짧게, 리프레시 토큰은 더 길게 발급하고 DB에는 해시만 저장한다.
- refresh 때 이전 토큰을 폐기하고 같은 family의 새 토큰으로 회전한다.
- 폐기된 토큰 재사용 감지 시 family 전체를 무효화한다.

### 로그아웃·화면

- 로그아웃은 현재 세션의 refresh token을 폐기한다(Bearer 토큰 방식, 쿠키 없음).
- 비로그인 화면은 회원가입·로그인만, 로그인 화면은 로그아웃·설정만 표시한다.
- 보호 API의 401 응답 시 세션을 정리하고 로그인 화면으로 이동한다.
- 테스트: 성공, 일반화된 실패, 잠긴 계정, 회전, 재사용, 로그아웃 후 접근, CSRF

## 5. FR-AUTH-04 회원탈퇴

| 항목 | 설계 |
|---|---|
| 단계 | MVP 보안·개인정보 필수 |
| API | `DELETE /v1/me` |
| 데이터 | 사용자 소유 데이터, 세션, 비식별 감사 로그 |
| 합격 기준 | AC-AUTH-05 |

### 흐름

1. 삭제되는 정보, 유지되는 비식별 감사 정보, 복구 가능 여부를 표시한다.
2. 비밀번호 계정은 현재 비밀번호로, 소셜 계정은 최근 재인증으로 확인한다.
3. 최종 확인 전에는 데이터를 변경하지 않는다.
4. 승인된 정책에 따라 즉시 삭제 또는 `DELETION_PENDING`으로 원자적으로 전환한다.
5. 모든 세션·예약·알림을 취소하고 현재 세션을 종료한다.

### 무결성·검증

- 공유 뉴스 데이터는 삭제하지 않고 사용자 연결 데이터만 제거한다.
- 감사 로그의 사용자 식별자는 정책에 따라 비식별화하며 비밀값을 남기지 않는다.
- 재요청은 같은 최종 상태를 반환하는 멱등 동작으로 설계한다.
- 테스트: 확인 취소, 재인증 실패, 성공, 중복 요청, 삭제 후 보호 API, 예약·세션 정리

## 6. FR-HOME-01 랭킹 카드

| 항목 | 설계 |
|---|---|
| 단계 | MVP |
| API | `GET /v1/news?category=AI&sort=rank&page_size=10` |
| 데이터 | `news`, `sources`, `content_results` |
| 합격 기준 | AC-HOME-01, AC-HOME-02 |

### 계약

각 항목은 `id`, `rank`, `title`, `source_name`, `published_at`, `category`, `summary_lines`,
`processing_status`, `original_url`에 더해 `original_language`, `author_name`(명시적
바이라인만 추출, 없으면 null)을 포함한다(v1.0.4). 공개 전 검증을 통과한 `READY` 결과를 우선하며
부족하면 실제 개수만 반환한다. 화면설계서의 3개 카드는 정적 샘플일 뿐 API 반환 개수를 3건으로 제한하지 않는다.
외국어 기사의 `title`은 파이프라인의 `원문 ||| 번역` 저장 형식에서 원문 부분만 표시한다.

### v1.0.3 정렬·페이지네이션 기준 (db-search 반영)

- **정렬 원칙**: `rank`/`latest` 모두 **발행 시각(`published_at`) 최신→과거 순**이 최우선이다.
  요청·로그인 시각을 기준으로 상대적 최신성을 평가하며, 오래된 기사가 품질 상태(READY)만으로
  새 기사보다 위에 오지 않는다. `rank`는 발행 시각 다음으로 품질(READY 우선)→출처 우선순위→ID를
  보조 정렬로 사용하고, `latest`는 발행 시각→ID 순이다.
- **목록 구성**: 실시간 수집·검색된 최신 기사와 DB에 저장된 기존 기사를 구분하지 않고
  `published_at DESC` 하나의 순서로 함께 나열한다. 오래된 DB 기사는 최신 기사 뒤에
  최신→과거 순으로 이어서 출력한다(제외하지 않음).
- **페이지 표시**: 화면은 페이지당 **4건**을 비동기로 가져와 기존 목록 뒤에 순차적으로
  이어 붙인다(무한 스크롤 + `더 보기` 버튼 병행). 목록 하단 600px 이내 진입 또는 버튼
  클릭 시 다음 커서 페이지를 fetch한다. 게스트는 `page_size<=10` 제한 응답을 그대로 표시한다.
- **상세·관련 뉴스**: 상세의 `related_news`도 목록과 동일하게 `published_at DESC`를
  최우선으로 하고 관련도 점수는 동률 보조 지표로 사용한다.

### 화면·동작

- 데스크톱은 순위, 기사 정보, AI 3줄 요약, 행동 영역을 가로로 배치하고 모바일은 세로로 재배치한다.
- 본문 상단에는 통합 검색, `전체`/`AI·기술` 필터와 `랭킹순`/`최신순` 정렬을 둔다.
- v1.0.4: 로그인 사용자에게는 `국내`/`해외` 지역 칩과 저장 관심사 집계 칩(최대 5개 +
  `더 보기`)을 추가로 제공하고, 비로그인 사용자에게는 카테고리·관심사 탐색 영역을
  숨긴다. 카드에는 `국내`/`해외`/`구분 미확인` 출처 태그와 `author_name`(있을 때)을 표시한다.
- 읽음 상태는 `GET /v1/news/activity`(건수·읽음 ID·`interest_counts`)와
  `GET /v1/news/read-state`로 조회하고 `PUT /v1/news/{id}/read`로 기록한다(모두 no-store).
- 카드 행동은 `원문 열기`와 `링크 복사`를 제공한다(1.0.4.1: `상세 보기` 제거). 카드 전체 클릭을 지원하더라도 각 버튼의 독립 의미와 키보드 접근을 유지한다.
- 제목 두 줄 말줄임 뒤에도 전체 제목을 접근 가능한 이름으로 제공한다.
- 처리 상태는 아이콘, 텍스트, 색상을 함께 사용하며 `READY`뿐 아니라 부분 상태도 동일한 위치에서 표현한다.

### 성능·검증

- query hash 기준 5분 캐시, 새 READY 결과 저장 후 관련 캐시 무효화
- N+1 없이 필요한 출처·콘텐츠를 함께 조회
- 테스트: 10건 순서, 7건만 존재, 긴 제목, UTC 변환, 캐시 hit/miss, 잘못된 상태 제외

## 14. FR-PIPE-01 수집

| 항목 | 설계 |
|---|---|
| 단계 | MVP |
| 실행 | Redis 큐를 소비하는 Python worker |
| 데이터 | `sources`, `news`, `jobs`, `job_attempts` |
| 합격 기준 | AC-PIPE-01 |

### 단계

1. 활성화된 승인 출처와 수집 창으로 dedupe key를 만든다.
2. Redis 잠금 획득 후 RSS·API·공식 HTML 어댑터를 실행한다.
3. 응답 scheme, DNS, redirect, 크기, Content-Type을 검증한다.
   v1.0.4부터는 검증한 공인 IP로 연결을 고정해 연결 시점 DNS 재조회(rebinding)를
   차단하고, HTML은 선언된 charset으로 디코딩한다.
4. 제목, canonical URL, 발행 시각, 안전한 텍스트를 공통 Pydantic 모델로 변환한다.
5. canonical URL unique와 정규화 제목 보조 기준으로 중복을 처리한다.
6. 신규 기사와 출처별 결과·오류를 트랜잭션으로 기록하고 후속 작업을 등록한다.

### 안전·실패

- robots.txt, 요청 간격, User-Agent, 타임아웃, 제한 재시도와 지터를 적용한다.
- 사용자 입력 URL은 수집기에 전달하지 않는다.
- 한 출처 실패가 다른 출처 결과를 삭제하거나 전체 작업을 실패시키지 않는다.
- 최대 재시도 후 dead-letter로 이동하고 원인 코드를 기록한다.
- 테스트: 신규·중복·부분 실패, 사설 IP, DNS 재바인딩, redirect, 큰 응답, 잘못된 MIME

- 본문이 부족하면 호출 없이 `INSUFFICIENT`와 `요약할 내용 부족`을 저장한다.
- v1.0.4: 영문 기사 제목의 `원문 ||| 한국어번역` 결합 저장에서 번역이 실패하면
  Google Translate 대신 LLM 제목 번역 백업 경로를 사용하고, 그래도 실패하면
  해당 기사를 저장하지 않아 다음 수집 주기에 재시도한다.

### 검증·재사용

- LLM 응답은 JSON Pydantic 모델로 검증하고 추가 필드를 거부한다.
- 수치·날짜·모델명·기관명은 원문 대조 규칙을 통과해야 READY가 된다.
- 내용 해시, 프롬프트 버전, 모델 ID가 같으면 기존 결과를 재사용한다.
- 사용자 개인정보, 계정, 검색 설정은 입력하지 않는다.
- 테스트: 한국어, 영어, 내용 부족, JSON 오류, 3줄 위반, 수치 변형, 타임아웃, 캐시 재사용

## 16. FR-PIPE-03 랭킹과 관련 뉴스

| 항목 | 설계 |
|---|---|
| 단계 | MVP 최소 규칙, 단계 3 고도화 |
| 데이터 | `news`, `sources`, `content_results`, `news_relations` |
| 합격 기준 | AC-HOME-01, 콘텐츠 관련 뉴스 검증 |

### MVP 랭킹 (v1.0.4 기준)

1. `published_at` 최신→과거가 모든 정렬의 최우선 기준이다(목록 `rank`·`latest`,
   관련 뉴스 공통). 오래된 기사가 품질 상태만으로 새 기사보다 위에 오지 않는다.
2. `rank` 정렬은 발행 시각 다음으로 품질(READY 우선)→승인된 출처 우선순위→ID 순을
   동률 보조 기준으로 사용한다.
3. `latest` 정렬은 발행 시각→ID 순이다.

조회수·언급량·급등률처럼 확보하지 못한 값을 만들지 않는다. 화면 도움말에 실제 기준을 설명한다.

### 관련 뉴스

- 동일 AI 카테고리 안에서 정규화 핵심 키워드와 제목 유사성의 단순 규칙으로 시작한다.
- 자기 자신, 중복 기사, 비공개·실패 기사는 제외한다.
- 관계에 `reason`과 `score`를 저장해 결과를 설명할 수 있게 한다.
- 테스트: 결정적 순서, 누락 지표, 동률, 무관 기사 제외, 자기 관계, 중복 pair

## 17. FR-PIPE-04 캐시와 재처리

| 항목 | 설계 |
|---|---|
| 단계 | MVP |
| 데이터 | `content_results`, `jobs`, `job_attempts`, Redis 캐시·잠금 |
| 합격 기준 | AC-PIPE-03, AC-STATE-01 |

### 캐시

- DB의 검증 완료 결과가 원본이며 Redis는 만료 가능한 조회 캐시다.
- 목록 5분, 상세 30분을 기본으로 하고 결과 변경 후 관련 키만 무효화한다.
- 화면 조회는 AI 작업을 생성하지 않는다.
- 캐시 장애 시 DB로 조회하고 캐시 실패 때문에 요청 전체를 실패시키지 않는다.
- v1.0.4: `pipeline_sync_service`가 목록 요청을 계기로 5분 간격 `pipeline`→`public`
  기사를 동기화한다(PostgreSQL 전용 daemon 스레드, canonical_url 중복 제외,
  SUCCESS 상태만, 요약 3줄 충족 시 READY·아니면 INSUFFICIENT). 동기화 실패는
  로그만 남기고 API 응답에 영향을 주지 않는다.

### 재처리

- 작업은 수집, 정제, 번역, 요약, 검증 단계를 기록한다.
- 실패 단계와 마지막 성공 단계, 시도 횟수, 일반화 오류 코드를 저장한다.
- 재처리는 실패 단계부터 시작하고 최대 횟수를 넘기면 dead-letter로 이동한다.
- 같은 dedupe key의 실행은 Redis 잠금과 DB unique 제약으로 이중 방어한다.
- 운영 재처리 UI는 시간 여유가 아니라 단계 3 승인 후 구현하며 MVP는 관리 명령으로 제한한다.
- 테스트: cache hit/miss, 무효화, Redis 단절, 단계 재개, 동시 실행, 잠금 만료, dead-letter
