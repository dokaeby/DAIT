# 구글 로그인 운영 적용 가이드 (배포 담당자용)

| 항목 | 값 |
|---|---|
| 대상 | 최종 배포 담당자 |
| 코드 상태 | 구글 로그인 코드는 `develop`에 반영되어 있다. 코드 작업은 필요 없다. |
| 할 일 | 구글 콘솔에서 로그인용 열쇠 만들기, 서버 환경변수 3개, DB 마이그레이션 2개, 확인 |
| 관련 문서 | `README.md`의 "구글 로그인" 절, `docs/decisions.md`(2026-11-13), 08·09 단위 테스트 문서 |

## 1. 먼저 알아 둘 것

- 코드는 환경변수 `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI` 세 값이 **모두** 있을 때만 구글 로그인을 켠다.
  모두 비어 있으면 `/v1/auth/google/*`가 404이고 기존 로그인은 그대로다. 일부만 있으면 **서버가 시작을 거부**한다.
- 운영(release)의 `GOOGLE_REDIRECT_URI`는 `https` 주소만 허용한다.
- 클라이언트 **보안 비밀번호는 코드·깃·채팅·로그에 남기지 않는다.** 서버 환경변수와 개인 `.env`에만 둔다.
- 구글 로그인 열쇠는 **팀 구글 계정**으로 만들어 개인 계정에 묶이지 않게 한다.

## 2. 순서 (이 순서를 지킨다)

1. 구글 콘솔 설정(3절) → 클라이언트 ID·보안 비밀번호 확보
2. 운영 DB 백업 확인
3. 배포 브랜치에 구글 로그인 코드가 반영되었는지 확인
4. **마이그레이션 먼저**(5절): `0008_social_identities`, `0009_merge_social_topics`
5. 서버 환경변수 3개 등록 후 재시작(4절)
6. 실제 로그인 확인(6절)

환경변수를 먼저 넣고 마이그레이션이 없으면 구글 로그인 시 DB 오류가 난다.

## 3. 구글 콘솔 설정 (팀 구글 계정, 약 10~20분)

화면 이름은 구글이 가끔 바꾸므로 비슷한 이름을 찾는다.

1. `console.cloud.google.com`에 팀 구글 계정으로 로그인한다.
2. 프로젝트 선택 → **새 프로젝트** → 이름 `dait`(또는 팀 규칙) → 만들기. 만든 프로젝트를 선택해 둔다.
3. ☰ → **API 및 서비스 → OAuth 동의 화면**(또는 "Google 인증 플랫폼 → 브랜딩")에서 **시작하기**.
   앱 이름 `DAIT`, 사용자 지원 이메일, 대상 **외부**, 연락처 이메일을 입력하고 만든다.
4. **데이터 액세스(범위)** → 범위 추가에서 `openid`와 `.../auth/userinfo.email`만 선택하고 저장한다. `profile`은 넣지 않는다.
5. **대상 → 테스트 사용자**에 시험할 팀원의 지메일을 추가한다. 앱을 게시하기 전에는 여기 등록된 계정만 로그인할 수 있다.
   (주소는 `@gmail.com`까지 정확히 입력한다.)
6. **클라이언트(사용자 인증 정보) → 클라이언트 만들기** → 유형 **웹 애플리케이션**, 이름 `dait-web`.
7. **승인된 리디렉션 URI**에 운영 주소를 한 글자도 틀리지 않게 추가한다. 끝에 `/`를 붙이지 않는다.
   - 예: `https://<운영 주소>/v1/auth/google/callback`
8. 만들기를 누르면 **클라이언트 ID**와 **클라이언트 보안 비밀번호**가 나온다. 창을 닫기 전에 안전한 곳(서버 환경변수)에 넣는다.
   비밀번호를 잃으면 같은 클라이언트에서 새 보안 비밀번호를 만들고 서버 값을 바꾼다.

## 4. 서버 환경변수 (Render 예시)

서비스 → **Environment** → **Add Environment Variable**로 세 개를 **함께** 넣고 저장한다(저장하면 재시작된다).

| 이름 | 값 |
|---|---|
| `GOOGLE_CLIENT_ID` | 3절 8번의 클라이언트 ID |
| `GOOGLE_CLIENT_SECRET` | 3절 8번의 보안 비밀번호 |
| `GOOGLE_REDIRECT_URI` | 3절 7번과 **똑같은** 주소 |

`APP_ENV`는 `release`(기본값)를 유지한다. 개인 컴퓨터의 `.env`는 깃에 올라가지 않으므로 서버에 따로 넣어야 한다.

## 5. DB 마이그레이션

- 새 마이그레이션: `0008_social_identities`(구글 연결 표, `users.password_hash` NULL 허용), `0009_merge_social_topics`(이력 합침, 표 변경 없음).
- Procfile은 마이그레이션을 자동으로 실행하지 않는다. 운영 DB에서 `python -m src.server migrate`를 실행한다
  (Render Shell 또는 배포 전 명령 등 팀이 쓰는 방식으로).
- 실행 전에 백업을 확인한다. 이미 적용된 DB에서는 다시 실행해도 안전하다.
- 롤백 주의: 구글 전용 계정(비밀번호 없음)이 생긴 뒤에는 `0008` downgrade가 의도적으로 중단된다(계정 보호). 문제가 생기면
  **마이그레이션을 되돌리기보다 환경변수 3개를 지워 기능을 끄는 것**이 안전하다.

## 6. 적용 후 확인

운영 주소에서 테스트 사용자로 등록한 계정으로 확인한다.

- [ ] 로그인 창에 "구글로 계속" 버튼이 보이고, 누르면 구글 계정 선택 화면이 열린다.
- [ ] 처음 쓰는 구글 계정: 가입되고 로그인된다(첫 로그인은 관심사 설정 화면).
- [ ] 같은 계정으로 다시 로그인하면 바로 로그인된다.
- [ ] 같은 이메일로 이메일 가입한 계정이 있으면 "구글 계정 연결" 창이 뜬다. "연결하기"(기존 비밀번호) 성공, "연결하지 않기"는 변화 없음.
- [ ] 구글 전용 계정 탈퇴: 로그인 5분 이내, 비밀번호 칸이 아니라 "탈퇴" 글자칸에 `탈퇴` 입력.
- [ ] 등록하지 않은 계정은 구글 화면에서 "액세스 차단됨"이 나온다(앱 게시 전이므로 정상).

## 7. 문제 해결

| 증상 | 원인과 조치 |
|---|---|
| 서버가 시작하지 않는다 | 환경변수 3개 중 일부만 있거나, `GOOGLE_REDIRECT_URI`가 https가 아니다. 로그 마지막 줄 확인 |
| 구글 화면에서 `redirect_uri_mismatch` | 콘솔 "승인된 리디렉션 URI"와 `GOOGLE_REDIRECT_URI`가 한 글자라도 다르다 |
| 로그인 후 "구글 로그인에 실패했습니다" | 쿠키가 따라가지 않은 경우(접속 주소와 리디렉션 주소의 호스트가 다름) 또는 클라이언트 ID 오타. 서버 로그의 `audit event=google_login outcome=` 값 확인 |
| "구글과 연결하지 못했습니다" | 서버가 구글 token 주소에 접속하지 못했거나 보안 비밀번호가 틀렸다 |
| `access_denied` | 테스트 사용자에 없는 계정이거나 사용자가 취소했다 |

서버 로그의 `audit event=google_login outcome=...` 줄에 실패 사유 코드가 남는다(비밀값은 기록되지 않는다):
`state_invalid`, `invalid_id_token`, `email_unverified`, `provider_unavailable`, `link_offered`, `google_account_mismatch`.

## 8. 앱 게시(선택)

콘솔 "대상"에서 게시 상태를 **프로덕션**으로 바꾸면 테스트 사용자 목록 없이 누구나 로그인할 수 있다.
`email`·`openid` 범위만 쓰므로 추가 심사 부담이 작지만, 구글의 안내 화면 요구사항은 게시 시점에 콘솔에서 확인한다.
