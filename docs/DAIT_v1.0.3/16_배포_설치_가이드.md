## 1. 전체 구성

```text
사용자 브라우저
    │ HTTPS
    ▼
Render Web Service "dait" ── FastAPI (dait.main:create_app, PYTHONPATH=src)
    │                    ├── 정적 프론트엔드 (/, /app.js, /settings.html, /news-ui.js)
    │                    └── /v1/* API
    │
    ├── DATABASE_URL ──▶ Supabase PostgreSQL (pooler, public 스키마)
    ├── REDIS_URL ─────▶ Render Key Value "dait-redis"
    └── ◀── cron-job.org ── POST /v1/internal/scheduler/tick

Render Web Service "dait-pipeline" ── src/backend/app 파이프라인
    ├── DAIT_DATABASE_URL ──▶ Supabase PostgreSQL (pipeline 스키마)
    ├── DAIT_GROQ_API_KEY ──▶ Groq LLM (없으면 xAI→Google Translate 폴백)
    └── DAIT_REDIS_HOST/PORT ──▶ dait-redis
```

- **Render**: 웹 서비스 2개(`dait` 통합 앱, `dait-pipeline` 수집·AI 처리) + Key Value 1개.
- **Supabase**: PostgreSQL DB. 계약 스키마는 `public`, 파이프라인은 `pipeline` 스키마로 분리.
- **cron-job.org**: 외부 스케줄 트리거. tick 엔드포인트를 주기적으로 호출한다.

## 3. Supabase PostgreSQL 설정

### 3.1 프로젝트 생성

1. https://supabase.com 에서 New Project 생성
2. Region은 서비스 사용자와 가까운 리전 선택 (예: Northeast Asia)
3. Database password 안전하게 보관

### 3.2 연결 문자열 확인

Supabase Dashboard → Project Settings → Database → Connection string에서 **URI** 탭의 값을 복사한다.

```text
# Session pooler (권장, 포트 5432)
postgresql://postgres.<project-ref>:<password>@aws-0-<region>.pooler.supabase.com:5432/postgres

# 또는 직접 연결 (포트 5432, IPv6 가능 환경만)
postgresql://postgres:<password>@db.<project-ref>.supabase.co:5432/postgres
```

> Render는 IPv4 아웃바운드만 지원하므로 **Supabase pooler URI를 사용**한다.
> `postgres` 슈퍼유저 대신 가능하면 전용 역할을 생성한다(DB 설계서: 앱 런타임 계정에 DDL 권한 금지).

### 3.3 전용 DB 역할 생성 (권장)

Supabase SQL Editor에서:

```sql
CREATE ROLE dait_app LOGIN PASSWORD '<강력한-비밀번호>';
GRANT CONNECT ON DATABASE postgres TO dait_app;
GRANT USAGE ON SCHEMA public TO dait_app;
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO dait_app;
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO dait_app;
ALTER DEFAULT PRIVILEGES IN SCHEMA public
  GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO dait_app;
```

### 3.4 마이그레이션 실행

로컬 또는 CI에서 `DATABASE_URL`을 Supabase로 지정하고 Alembic을 실행한다.

```bash
cd src/backend
DATABASE_URL="postgresql://dait_app:<pw>@aws-0-<region>.pooler.supabase.com:5432/postgres" \
  uv run alembic upgrade head
```

> 앱은 `DATABASE_URL` 스킴만으로 백엔드를 자동 선택한다(`repositories/db.py` 디스패처).
> `postgresql://`/`postgres://`/`postgresql+psycopg://` → psycopg3 백엔드(`db_postgres.py`),
> `sqlite:///` → sqlite 백엔드(`db_sqlite.py`, 로컬 개발용). 별도 코드 변경 없이 전환된다.
> SQL 차이(`?`→`%s`, bool, 시각 정규화)는 백엔드 계층이 흡수하며 저장소 SQL은 공통이다.

## 4. Render 배포

### 4.1 Web Service 생성

1. Render Dashboard → New → Web Service → GitHub 저장소 선택
2. 설정:

| 항목 | 값 |
|---|---|
| Runtime | Python 3 (>=3.12) |
| Root Directory | `src/backend` |
| Build Command | `pip install uv && uv sync --frozen` |
| Start Command | `PYTHONPATH=src uvicorn --factory dait.main:create_app --host 0.0.0.0 --port $PORT` |

> `dait` 패키지는 `src/backend/src/dait`에 있고 이 프로젝트는 pip 설치 대상이 아니라
> `PYTHONPATH`로 임포트한다. Render의 rootDir이 `src/backend`이므로 작업 디렉터리 기준
> 상대경로 `src`가 `src/backend/src`를 가리킨다. `create_app` 팩토리가 정적 프론트엔드와
> `/v1/*` API를 함께 서빙한다.

### 4.2 환경 변수

Render Dashboard → Environment에서 설정한다.

| 변수 | 값 | 필수 |
|---|---|---|
| `DATABASE_URL` | Supabase pooler URI (3.2절). `postgresql://` 접두사 그대로 사용 | O |
| `JWT_SECRET` | 충분히 긴 랜덤 문자열 (`openssl rand -hex 32`) | O |
| `SCHEDULER_TICK_SECRET` | cron-job.org 호출 인증용 랜덤 문자열 | O (tick 사용 시) |
| `APP_ENV` | `release` | 권장 |
| `REDIS_URL` | Render Key Value 접속 문자열 | 권장(미설정 시 인메모리 fallback) |
| `SCHEDULER_TICK_SECRET` | cron-job.org 호출 인증용 랜덤 문자열 | O (tick 사용 시) |

> 비밀값은 절대 코드·문서에 커밋하지 않는다. Render 환경변수로만 주입한다.

### 4.3 헬스 체크

- `GET /healthz` → `{"status":"ok"}`
- `GET /readyz` → `{"status":"ready"}` (DB 연결 + Redis 설정 시 Redis 연결 검사, 실패 시 503)

Render Health Check Path에 `/healthz`를 지정할 수 있다.

### 4.4 확인

배포 후 `https://<서비스명>.onrender.com/` 접속:

- 뉴스 목록 표시 (파이프라인이 수집한 데이터가 ETL로 계약 스키마에 있어야 함)
- 회원가입/로그인 동작 (Bearer 토큰 발급)
- `/settings.html` 설정 저장
- 로그인·가입 제출 즉시 진행 팝업 표시 → 응답 완료 시 자동 닫힘

### 4.5 로컬 개발 (SQLite)

서버 배포 없이 로컬에서 실행할 때는 `DATABASE_URL`을 비워 두거나 sqlite 경로를 지정한다.

```bash
cd src/backend
# 최소 실행에 필요한 환경변수
export JWT_SECRET="$(openssl rand -hex 32)"
export APP_ENV=debug
export DATABASE_URL="sqlite:///./dait_api.db"

uv run alembic upgrade head          # 스키마 생성 (최초 1회)
uv run uvicorn dait.main:app --reload --port 8000
```

- `dait_api.db`는 로컬 전용 파일이며 git에 커밋하지 않는다(`.gitignore`의 `*.db`).
- `/docs`(Swagger UI)는 `APP_ENV=debug`일 때만 열린다.
- 뉴스 데이터가 필요하면 `src/backend/app`(KAN-10)의 수집기를 실행하거나 기존 `dait.db` 데이터를 이관한다.

### 4.6 파이프라인 서비스 (`dait-pipeline`)

뉴스 수집·AI 처리(요약·번역)는 별도 Render Web Service로 배포한다.

| 항목 | 값 |
|---|---|
| Name | `dait-pipeline` |
| Root Directory | `src/backend` |
| Build Command | `pip install uv && uv sync --frozen` |
| Start Command | `PYTHONPATH=src uvicorn --factory app.api.main:app --host 0.0.0.0 --port $PORT` |

환경 변수:

| 변수 | 값 | 설명 |
|---|---|---|
| `DAIT_DATABASE_URL` | Supabase pooler URI + `?options=-c search_path=pipeline` | 파이프라인 전용 스키마 |
| `DAIT_ENABLE_LIVE_RSS` | `true` | 실제 RSS 수집 활성화 |
| `DAIT_GROQ_API_KEY` | Groq API 키 | 없으면 xAI→Google Translate→regex 폴백 |
| `DAIT_REDIS_HOST` / `DAIT_REDIS_PORT` | `dait-redis` 접속 정보 | 선택 |

- Supabase에 `pipeline` 스키마를 미리 생성하고 `search_path`로 분리한다(계약 스키마와 테이블명 충돌 방지).
- 시작 시 해당 스키마 DB가 비어 있으면 RSS 수집→AI 처리 bootstrap이 자동 실행된다.
- 수집 결과를 계약 스키마(`public.news` 등)로 반영하려면 ETL 동기화가 필요하다(현재 수동/스크립트).

## 5. cron-job.org 등록

### 5.1 잡 생성

1. https://cron-job.org 가입 → Create cronjob
2. 설정:

| 항목 | 값 |
|---|---|
| Title | `dait-scheduler-tick` |
| URL | `https://<render-서비스명>.onrender.com/v1/internal/scheduler/tick` |
| Schedule | Every 5~15 minutes (예: `*/10 * * * *`) |
| Request method | POST |
| Headers | `Authorization: Bearer <SCHEDULER_TICK_SECRET>` |
| Save response | Yes (디버깅용) |

3. Save → 즉시 "Run now"로 1회 테스트

### 5.2 tick 수신 시 서버가 하는 일 (v1.0.3 구현 기준)

API 설계서 7.5절 / 시스템설계서 5.3절 기준:

1. `enabled`이고 `next_run_at <= now`인 `schedules` 조회
2. 예약별 `schedule_runs` 생성 (`dedupe_key` UNIQUE — 중복 tick은 건너뜀)
3. `next_run_at`을 다음 실행 시각(UTC)으로 재계산
4. FastAPI `BackgroundTasks`로 예약 조건 검색을 비동기 실행 → 결과를
   `schedule_run_items`에 저장 (실패 시 최대 3회 재시도)
5. `notification_deliveries` 생성 — 카카오 발송기 미연결 시 `NOT_CONFIGURED` 기록
6. `200 {status, tick_at, due_schedules, jobs_created, jobs_skipped, notifications_created}` 응답
7. 사용자는 `GET /v1/me/schedule-runs`로 결과 조회, `POST /v1/me/schedule-runs/seen`으로 확인 표시

### 5.3 주의 사항

- **Render Free 플랜은 스핀다운**이 있어 첫 요청이 50초+ 지연될 수 있다. cron 호출이 cold start를 유발하므로 tick 응답이 느릴 수 있다. Production 플랜 권장.
- tick 실패(5xx/타임아웃)는 cron-job.org가 재시도 로그를 남기며, `schedule_runs.dedupe_key`로
  작업 자체는 멱등하므로 중복 실행되지 않는다.
- 검색은 tick을 받은 API 프로세스의 `BackgroundTasks`에서 실행되므로 별도 worker가 필요 없다.
- 파이프라인(`dait-pipeline`)은 시작 시 DB가 비어 있으면 1회성 bootstrap 수집을 수행한다.
  주기적 수집이 필요하면 tick 경로나 서비스 재시작으로 트리거한다.

> **v1.0.3 구현 상태**: tick 엔드포인트·`SCHEDULER_TICK_SECRET` 검증·`schedule_runs` 이력·
> Redis 연동은 모두 구현·배포 완료. E2E 검증: 예약 생성→tick(`due_schedules:1`)→실제 검색
> SUCCEEDED→결과 10건 저장→`GET /v1/me/schedule-runs` 조회까지 확인했다.

## 7. 트러블슈팅

| 증상 | 원인 | 조치 |
|---|---|---|
| tick 401 | `SCHEDULER_TICK_SECRET` 불일치 | Render env와 cron-job.org 헤더 값 비교 |
| tick 503 | DB/Redis 연결 실패 | `DATABASE_URL` pooler URI 확인, Supabase 상태 확인 |
| 뉴스 목록 빈 화면 | 마이그레이션 미실행 또는 데이터 없음 | `alembic upgrade head` + 수집 작업 실행 |
| 로그인 실패 | `JWT_SECRET` 미설정/변경 | env 확인, 기존 토큰은 secret 변경 시 무효화됨 |
| tick은 오는데 jobs_created=0 | `next_run_at`이 미래 | schedules의 timezone/local_time/next_run_at 확인 |
| tick 200인데 검색 결과 없음 | BackgroundTasks 비동기 지연 또는 검색 실패 | `schedule_runs.search_status`/`search_error` 확인, 최대 3회 재시도 후 FAILED |
| 앱 시작 시 `ValidationError: database_url` | `DATABASE_URL` 스킴 오타 | `sqlite:///`, `postgresql://`, `postgres://` 중 하나인지 확인 |
| `/readyz` 503, DB 연결 실패 | pooler URI·비밀번호·역할 권한 | 3.3절 GRANT 재확인, pooler 호스트/포트(5432) 확인 |
| 마이그레이션 시 `Can't locate revision` | `alembic upgrade head`를 잘못된 디렉터리에서 실행 | `src/backend`에서 실행하고 `alembic.ini` 경로 확인 |
| psycopg 연결 타임아웃 | Supabase pooler 모드/리전 불일치 | Session pooler(5432) 사용, IPv4 전용 호스트 확인 |
