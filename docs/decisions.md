# DAIT 결정 기록

## 2026-11-04: 문서 기준선 1.0.0

- 결정: FastAPI와 JavaScript 반응형 웹을 구현 기준으로 사용하고 PyQt6 데스크톱 앱은 제외한다.
- 이유: 통합 기획서의 확정 스택과 `docs/AI-config/AGENTS.md`의 기술 범위를 일치시킨다.
- 영향: `docs/v1.0.0/02_전체설계서.md`의 실행·배포 구조.

## 2026-11-04: MVP 범위

- 결정: AI 단일 카테고리, 이메일·비밀번호 인증, 수집·번역·3줄 요약, 목록·검색·상세를
  단계 1로 고정한다.
- 이유: `AGENTS.md`의 개발 단계가 소셜 로그인·개인화·알림보다 MVP 완성을 우선한다.
- 영향: 소셜 로그인과 FR-SET-01~03은 단계 2, 카테고리 확장은 단계 3으로 이동한다.

## 2026-11-04: 화면 기준

- 결정: 첨부된 밝은 화이트 대시보드를 반응형 UI 기준으로 채택한다.
- 이유: 데스크톱과 모바일의 정보 구조가 함께 제시되어 있고 핵심 뉴스 탐색 흐름과 일치한다.
- 영향: MVP에서 동작하지 않는 카테고리·관심·저장·알림 메뉴는 노출하지 않는다.

## 2026-11-04: MVP 랭킹

- 결정: `품질 검증 통과 > 발행 시각 > 출처 우선순위 > 안정적인 ID` 순서를 사용한다.
- 이유: 조회수·언급량처럼 확보되지 않은 지표를 만들지 않고 결정적 결과를 제공한다.
- 영향: 고급 개인화와 외부 지표 기반 랭킹은 단계 3에서 재검토한다.

## 2026-11-04: 작업 처리

- 결정: Redis 큐를 읽는 작은 Python worker로 시작하고 별도 작업 프레임워크를 도입하지 않는다.
- 이유: 현재 기능에 필요한 최소 구조이며 미사용 추상화와 새 의존성을 피한다.
- 영향: 처리량 또는 운영 복잡도가 실제로 증가할 때 측정 결과를 근거로 재검토한다.

## 2026-11-13: 구글 로그인과 이메일 계정 병합 금지

- 결정: 구글 로그인은 OIDC Authorization Code + PKCE(S256)로 구현하고, 계정 연결은 이메일이
  아니라 불변 값 `sub`로만 한다. 같은 이메일의 기존 계정이 있으면 합치지 않고 `email_in_use`로
  안내한다. 구글 전용 계정은 `password_hash`가 NULL이다.
- 이유: 이메일 가입은 소유 확인을 하지 않아, 공격자가 남의 이메일로 먼저 가입해 두면 자동 병합 시
  피해자의 구글 로그인이 공격자가 만든 계정으로 이어진다(사전 계정 탈취).
- 영향: id_token 서명 검증은 하지 않는다(구글 token 엔드포인트와 TLS 직접 통신으로 받은 토큰은
  OIDC Core 3.1.3.7이 TLS 검증으로 대신하도록 허용). 토큰 발급 경로는 이메일 로그인과 같다.
  구글 전용 계정의 탈퇴는 로그인 5분 이내 + "탈퇴" 입력으로 확인한다. 되돌리기 어려운 점:
  마이그레이션 0008은 비밀번호 없는 계정이 생긴 뒤에는 downgrade가 거부된다.
  설정 화면의 "구글 계정 연결"(로그인한 본인이 직접 연결하는 안전한 병합)은 다음 단계 후보다.
- 키 교체: 구글 콘솔 > 사용자 인증 정보 > 해당 클라이언트에서 보안 비밀번호를 재설정하고,
  `.env`와 배포 서버의 `GOOGLE_CLIENT_SECRET`을 함께 바꾼 뒤 서버를 다시 시작한다.
