# DAIT 기획서

| 항목 | 값 |
|---|---|
| 문서 버전 | 1.0.0 |
| 기준일 | 2026-11-04 |
| 상태 | 승인 대기 개발 기준선 |
| 대상 | 5인 개발팀, 발표 담당자, 검수 담당자 |

## 1. 제품 정의

DAIT는 신뢰할 수 있는 출처의 AI 뉴스를 서버에서 주기적으로 수집하고, 한국어 번역과
근거 기반 3줄 요약을 생성해 반응형 웹으로 제공하는 뉴스 큐레이션 서비스다.

사용자는 긴 원문을 모두 읽기 전에 핵심을 빠르게 파악하고, 출처와 원문으로 이동해 사실을
확인할 수 있다. 서비스는 원문을 대신하는 매체가 아니라 발견·이해·검증을 돕는 도구다.

## 2. 해결할 문제

- AI 뉴스가 여러 사이트에 흩어져 있어 매일 직접 확인해야 한다.
- 해외 원문은 언어와 길이 때문에 핵심 파악에 시간이 든다.
- 출처가 불명확한 요약은 사실 검증이 어렵다.
- 수집·AI 처리 실패가 사용자 화면에서 정상 기사처럼 보일 수 있다.
- 같은 기사를 반복 처리하면 비용과 응답 시간이 증가한다.

## 3. 목표와 비목표

### 3.1 목표

- 검증된 AI 뉴스 목록과 상세를 저장 결과 기준으로 1초 내 표시하는 것을 목표로 한다.
- 모든 카드와 상세에서 출처, 발행 시각, 처리 상태, 원문 링크를 확인할 수 있게 한다.
- 해외 원문을 한국어로 번역하고 핵심을 3줄로 요약한다.
- 제목·요약 검색, 초기화, 로딩·빈·오류 상태를 일관되게 제공한다.
- 수집 또는 AI 제공자 하나가 실패해도 저장된 결과로 서비스가 계속 응답하게 한다.
- 개인정보, 자격 증명, 원문 저작권과 외부 URL 처리 안전을 기본 품질로 둔다.

### 3.2 비목표

- 원문 전체의 무단 저장·재배포
- 실시간 속보 경쟁이나 사용자 생성 콘텐츠
- MVP의 다중 카테고리, 결제, 추천 알고리즘, 외부 메신저 연동
- 사용자 요청 시 임의 URL을 서버가 즉시 가져오는 기능
- PyQt6 앱과 웹의 동시 개발
- 실제 수치가 없는 급등률, 조회수 또는 진행률의 생성

## 4. 대상 사용자

| 사용자 | 필요 | 대표 행동 |
|---|---|---|
| AI 동향을 빠르게 확인하는 일반 사용자 | 짧고 출처가 분명한 요약 | 목록 탐색, 검색, 상세 확인, 원문 열기 |
| 개발자·기획자 | 모델명·수치·기관명이 보존된 번역 | 키워드 검색, 원문 대조 |
| 운영 담당자 | 실패 원인과 재처리 가능 상태 | 작업 상태 확인, 실패 건 추적 |
| 관리자 | 출처와 품질·보안 통제 | 출처 활성화, 감사 로그 확인 |

## 5. 제품 원칙

1. 출처가 요약보다 우선한다.
2. 모르는 내용은 생성하지 않고 `내용 부족` 또는 `처리 실패`로 표시한다.
3. 결과가 없거나 적으면 실제 개수만 보여준다.
4. 색상만으로 상태나 검색 일치를 전달하지 않는다.
5. 화면 요청 중 AI를 호출하지 않고 선처리된 결과를 재사용한다.
6. 공개 기사 외 개인정보를 LLM이나 외부 API로 보내지 않는다.
7. 사용하지 않는 확장점과 동작하지 않는 버튼을 미리 만들지 않는다.

## 6. 범위와 단계

### 6.1 단계 1: MVP

| 기능 ID | 기능 | 범위 |
|---|---|---|
| FR-AUTH-01 | 이메일 회원가입 | 이메일, 비밀번호, 약관 동의, 안전한 해시 |
| FR-AUTH-03 | 로그인·로그아웃 | 짧은 액세스 토큰, 회전 리프레시 토큰, 전체 무효화 |
| FR-AUTH-04 | 회원탈퇴 | 재확인, 세션 종료, 삭제·비식별화 정책 적용 |
| FR-HOME-01 | 랭킹 카드 | AI 뉴스 최대 10개, 출처·시각·요약·상태 |
| FR-SEARCH-01 | 검색·초기화 | 제목·요약 검색, 형태를 포함한 강조 |
| FR-HOME-02 | 상태 화면 | 로딩, 결과 없음, 수집 실패, AI 실패 구분 |
| FR-DETAIL-01 | 상세 콘텐츠 | 원본 정보, 번역, 3줄 요약, 관련 뉴스 |
| FR-DETAIL-02 | 원문 동작 | 새 탭 열기, 링크 복사 피드백 |
| FR-PIPE-01 | 수집 | 승인 출처, 공통 형식, 중복 제거, 출처별 실패 |
| FR-PIPE-02 | 번역·요약 | 공개 기사만 처리, 검증 가능한 구조화 결과 |
| FR-PIPE-03 | 랭킹·관련 뉴스 | 실제 보유 지표 기반의 설명 가능한 기준 |
| FR-PIPE-04 | 캐시·재처리 | 결과 저장, TTL 캐시, 실패 원인과 시도 기록 |

MVP의 기능 카테고리는 `AI` 하나다. 첨부 화면의 금융·경제, 과학·산업 메뉴는 단계 3 전에는
노출하지 않는다.

### 6.2 단계 2: 계정과 개인화

- FR-AUTH-02: Google·Kakao·Apple 소셜 로그인. 제공자 ID 기준으로 연결하며 이메일만으로
  자동 병합하지 않는다.
- 이메일 6자리 2차 인증, 비밀번호 변경·재설정
- FR-SET-01~03: 예약, 관심 키워드·출처·카테고리, 노출 수, 웹·메일 알림
- 개인정보·세션 관리 화면과 알림 전달 기록

### 6.3 단계 3: 확장

- 카테고리 확장과 카테고리별 탐색
- 검색 고도화와 장기 사용 데이터 기반 개인화 추천
- 운영 모니터링, 처리량·실패율·비용 대시보드
- 승인된 외부 채널 연동 검토

## 7. 핵심 사용자 흐름

### 7.1 가입과 탐색

1. 사용자가 이메일과 정책 충족 비밀번호로 가입한다.
2. 로그인 후 AI 뉴스 목록으로 이동한다.
3. 최대 10개의 랭킹 카드를 보거나 검색어로 좁힌다.
4. 카드를 열어 원본 정보, 번역, 요약과 관련 뉴스를 확인한다.
5. 원문 링크를 새 탭에서 열어 사실을 대조한다.

### 7.2 실패와 복구

1. 저장된 정상 결과는 외부 제공자 상태와 관계없이 표시한다.
2. 실패 항목은 수집 실패, 본문 부족, 번역 실패, 요약 실패를 구분한다.
3. 운영자는 실패 단계와 마지막 시도를 확인한다.
4. 재처리는 성공한 앞 단계를 재실행하지 않고 실패 단계부터 시작한다.

## 8. 정보 구조와 화면 기준

### 8.1 데스크톱

- 상단: DAIT 로고, 서비스 설명, 알림 진입점(단계 2), 설정·계정
- 좌측: 오늘의 AI 뉴스, 현재 지원 카테고리, 단계 2 이후 관심·저장·최근 열람
- 본문: 제목, 설명, 통합 검색, 필터·정렬, 랭킹 카드
- 카드: 순위, 제목, 출처, 시각, 카테고리, 3줄 요약, 처리 상태, 상세·원문 버튼

### 8.2 모바일

- 상단에는 로고와 계정 진입점을 유지한다.
- 검색과 카테고리는 한 줄 스크롤 또는 줄바꿈으로 제공한다.
- 카드 내용은 제목, 메타데이터, 요약, 행동 순으로 세로 배치한다.
- 하단 탐색은 현재 제공하는 메뉴만 포함한다.

### 8.3 시각·접근성

- 첨부 화면의 흰 배경, 파란 강조색, 둥근 카드와 넓은 여백을 기준으로 한다.
- 본문 대비는 WCAG AA를 목표로 하며 키보드만으로 주요 흐름을 수행할 수 있어야 한다.
- 포커스 표시를 제거하지 않고, 아이콘 버튼에는 접근 가능한 이름을 제공한다.
- 상태는 아이콘·텍스트·색상을 함께 사용한다.
- 긴 제목은 두 줄 뒤 말줄임, URL은 안전하게 줄바꿈한다.

## 9. 콘텐츠와 랭킹 정책

- 1차 출처는 robots.txt, 이용약관, RSS/API 제공 여부를 검토해 승인한다.
- 공식 RSS·API·공식 사이트를 우선하고 소셜 사이트 비공식 우회 수집은 하지 않는다.
- 중복은 정규화 URL을 1순위, 정규화 제목을 보조 기준으로 판단한다.
- MVP 랭킹은 `품질 검증 통과 여부 > 발행 시각 > 출처 우선순위`로 고정한다.
- 관련 뉴스는 공통 정규화 키워드와 카테고리로 계산하고 근거를 저장한다.
- 조회수나 언급량이 없으면 해당 값을 랭킹에 사용하지 않는다.

## 11. 정책

### 11.1 개인정보

- 필수 수집: 이메일, 비밀번호 해시, 계정 상태, 보안 이벤트 시각
- 단계 2 추가: 관심 설정, 예약, 알림 채널 설정
- 탈퇴 시 법적 보관 의무가 없는 개인정보와 설정은 삭제하고 감사 기록은 비식별화한다.
- 비밀번호, 토큰, 인증코드는 로그에 남기지 않는다.

### 11.2 보안

- 비밀번호는 Argon2id 또는 bcrypt로 해시하고 유출 비밀번호를 차단한다.
- 쿠키 사용 시 `HttpOnly`, `Secure`, `SameSite=Lax` 이상과 CSRF 방어를 적용한다.
- 계정·IP 단위 속도 제한과 계정 열거 방지 응답을 적용한다.
- 사용자 소유 자원은 서버가 인증 사용자 ID로 조회해 IDOR을 방지한다.

### 11.3 저작권

- 제목, 출처, URL, 발행 시각, 필요한 최소 추출 텍스트와 생성 결과만 저장한다.
- 화면에는 출처와 원문 링크를 항상 표시한다.
- 원문 전체 열람은 원 사이트에서 수행한다.

## 12. 결정 사항과 미결 사항

### 12.1 이 버전에서 확정

- 밝은 반응형 웹 디자인 채택
- MVP 단일 AI 카테고리와 이메일·비밀번호 인증
- 5개 또는 10개 중 MVP 기본 노출 수는 최대 10개
- 랭킹 기준은 품질, 최신성, 출처 우선순위
- 인앱·메일 알림과 예약은 단계 2

### 12.2 구현 전 결정 게이트

| 우선순위 | 항목 | 완료 시점 |
|---|---|---|
| P0 | 1차 승인 출처와 대체 출처 | 수집 개발 전 |
| P0 | 5인 역할의 실명과 백업 | 스프린트 시작 전 |
| P0 | 개인정보 보관·탈퇴 삭제 방식 | 인증 API 고정 전 |

| P1 | 소셜 제공자별 앱 등록 정보 | 단계 2 시작 전 |
| P1 | 예약별 출처 또는 공통 출처 정책 | 단계 2 데이터 모델 고정 전 |
| P1 | 인앱 알림과 Web Push 범위 | 단계 2 UI 고정 전 |

## 13. 완료 정의

- MVP 기능의 API·화면·백그라운드 작업이 하나의 Docker Compose 실행 흐름에서 연결된다.
- 정상·빈·실패·권한 없음 상태를 실제 화면에서 확인한다.
- 발표 뉴스 10건의 출처, 수치, 고유명사, 번역과 요약을 원문 대조한다.
- ruff, pyright, pytest, pre-commit, gitleaks와 필요한 경우 pip-audit가 통과한다.
- release 모드에서 문서 UI, 상세 오류, SQL 에코와 민감 로그가 비활성화된다.
- 깨끗한 브라우저에서 가입, 로그인, 목록, 검색, 상세, 원문 열기, 로그아웃이 동작한다.
- 시연 데이터와 외부 제공자 장애용 백업 데이터를 준비한다.
