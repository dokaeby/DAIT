# 백그라운드 요약 직접 확인

실제 프로젝트: C:/DAIT_test/DAIT_ui

## 실행 (PowerShell)

기존 서버를 종료하고 Ollama가 실행 중인지 확인합니다. 기존 qwen3:4b를 사용하며 추가 패키지는 없습니다.

첫 번째 터미널:

~~~powershell
cd C:\DAIT_test\DAIT_ui
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
~~~

메인에서 Ctrl+F5로 새 스크립트를 읽습니다. 서버 시작 시 기존 미처리 기사도 자동으로 처리하며, 실행 중에는 창을 열지 않아도 계속 처리합니다. 요청당 최대 600초이며 CPU에서는 오래 걸릴 수 있습니다.

두 번째 터미널에서 새 기사 수집:

~~~powershell
cd C:\DAIT_test\DAIT_ui
.\.venv\Scripts\python.exe -m backend.pipelines.collect_news
~~~

수집 실패 시 기존 기사 DB를 보존하는 기존 동작은 유지합니다. 성공적으로 저장되면 작업자가 약 10초 안에 대상을 확인합니다. 이미 처리 중인 기사가 있으면 새 기사는 대기열에서 기다립니다.

## 브라우저 확인

1. 메인에서 처리 완료·재사용 / 대기·처리 중 / 재시도 종료 수를 확인합니다.
2. 생성 버튼을 누르지 않아도 요약이 순차적으로 카드에 나타나는지 확인합니다. 관심사 때문에 현재 목록에 처리 대상 기사가 없으면 완료 수만 달라질 수 있습니다.
3. 상세 팝업에서 같은 요약을 확인하고, 계정 전환 후 같은 기사에 같은 요약이 표시되는지 확인합니다.
4. 같은 기사 데이터를 다시 수집했을 때 정상 요약이 재사용되는지 확인합니다. 서버 재시작 후에도 저장 요약과 대기열이 유지되어야 합니다.
5. Ollama 중지 시 실패가 성공으로 표시되지 않고 재시도·종료 수에 반영되는지 확인합니다. 재시도 간격은 60초, 300초이며 최대 3회입니다. 재시도 종료 뒤 복구한 국내 기사는 상세 팝업의 생성 버튼으로 다시 대기열에 넣을 수 있습니다.

이 단계는 FastAPI 진입점에 연결했습니다. 이전 python -m backend.news 진입점에서는 자동 작업자가 시작되지 않습니다. 서버 종료 시 진행 중 요청을 강제로 취소하지는 않으며 프로세스 종료로 중단된 작업은 다음 시작 때 남은 횟수 안에서 재개합니다. 기존 CLI 요약/번역 명령을 자동 작업자와 동시에 실행하지 마세요.

작성만 완료했고 실행 검증은 사용자 확인을 기다립니다.
