# 10단계: 키워드 검색과 키워드+임베딩 검색 비교

웹 화면에서 유사도와 두 검색 방식의 결과를 확인할 수 있습니다. 기존 메인화면은 실시간 키워드 검색과 검색 버튼을 유지하며, 별도의 유사도 비교 화면에서 임베딩을 테스트합니다.

## 브라우저에서 확인

화면 서버를 재시작한 뒤 메인화면의 **임베딩 유사도 확인**을 누르거나 http://127.0.0.1:8000/search-lab 에 접속하세요.

1. **색인 준비·갱신**을 누릅니다. 모델 준비와 기사별 색인 진행 상태가 화면에 표시됩니다. 최초에는 모델 파일을 다운로드할 수 있습니다.
2. 검색어와 최소 유사도를 입력하고 **유사도 비교**를 누릅니다.
3. 키워드 결과, 의미 유사도 결과, 혼합 결과 세 목록에서 기사별 코사인 점수를 확인합니다. 제목을 누르면 상세 화면을 새 탭에서 확인할 수 있습니다.

코사인 유사도는 -1부터 1까지의 값이며 높을수록 검색어와 기사 입력의 의미가 가깝다는 뜻입니다. 정확도나 확률의 백분율이 아닙니다. 혼합 순위의 RRF 점수는 코사인 유사도와 별도로 표시합니다. 최소 유사도보다 낮은 키워드 일치 기사도 실제 코사인 값을 표시합니다.

로그인 계정의 관심사 범위를 두 방식에 똑같이 적용합니다. 계정 변경은 메인화면에서 하세요. 작업은 서버에서 하나씩 실행하며 완료·오류는 브라우저에서 확인합니다. 서버가 실행되는 동안 모델을 메모리에 재사용하므로 모델·패키지를 교체했다면 서버를 재시작하고 색인을 갱신하세요.

아래의 터미널 명령은 개발용 선택 사항입니다. 기능 테스트 결과는 위 브라우저 화면에서 확인하면 됩니다.

## 준비와 색인 생성

가상환경에 Sentence Transformers를 설치합니다. 임베딩은 Python 프로세스 안에서 CPU로 실행하며 Ollama 서버가 필요하지 않습니다. 기본 모델은 다국어용 `BAAI/bge-m3`입니다. 기존 요약·번역의 Ollama 사용과는 별개입니다.

```cmd
python -m pip install -r ui_step4\requirements.txt
```

가상환경이 활성화된 터미널에서 DAIT_ui 폴더를 기준으로 실행하세요. 첫 build 실행 때 Hugging Face에서 모델 파일을 다운로드하므로 인터넷 연결과 저장 공간이 필요합니다. 라이브러리와 모델은 가상환경·모델 캐시에 각각 저장됩니다. 기사 내용은 로컬에서 인코딩합니다.

```cmd
python ui_step4\search_compare.py build --status
python ui_step4\search_compare.py build
```

`--status`는 모델을 로드하거나 다운로드하지 않고 로컬 DB만 읽어 현재 기사 입력과 색인 일치 여부를 확인합니다. 생성은 전체 기사(현재 50개)의 제목·RSS 설명·저장된 해외 한국어 제목을 사용합니다. 기존 AI 요약은 비교 입력에 추가하지 않습니다. `ui_step4/search_index.db`에 벡터와 입력 해시, 모델·라이브러리 버전을 저장하며 원래 기사·요약 DB는 변경하지 않습니다.

기사 또는 번역 제목, 모델 커밋, 라이브러리 버전이 변경되면 build를 재실행하세요. 기존 일치 색인은 재사용합니다. 중단해도 완료된 기사는 남습니다. 강제 재생성은 `build --force`입니다. 기존 Ollama 모델 색인은 삭제하지 않으며 새 모델의 벡터와 섞지 않습니다. 로컬 CPU에서 실제 소요 시간은 실행 후 확인이 필요합니다. 입력이 모델의 토큰 한도를 초과하면 자르지 않고 오류로 안내합니다.

다운로드 완료 후 모델 캐시만 사용하려면 생성과 비교 명령에 `--offline`을 추가하세요. 모델 버전을 고정하려면 양쪽 명령에 동일한 `--revision 모델커밋`을 사용합니다. 기본값 `main`은 온라인 실행 시 최신 모델 파일을 확인합니다. 이전의 Ollama용 `--timeout` 옵션은 제거했습니다.

## 같은 검색어로 비교

```cmd
python ui_step4\search_compare.py compare --query "반도체"
python ui_step4\search_compare.py compare --query "개인정보 유출" --user user2
```

비로그인은 전체 기사에서, 사용자를 지정하면 해당 관심사와 일치하는 기사 안에서 두 방식을 비교합니다. 후보 범위는 양쪽이 같습니다. 비교 실행 때 Sentence Transformers 모델을 로드하고 검색어 한 건을 로컬에서 인코딩합니다. 기사 색인이 빠졌거나 입력·모델·라이브러리 버전이 달라졌다면 비교를 중단하고 재생성을 안내합니다.

## 이번 테스트의 순위 기준

- 키워드: 기존 화면과 같은 부분 문자열 일치입니다. 여러 단어를 모두 포함하는 기사를 최신순 최대 10개 표시합니다.
- 혼합: 키워드 후보 상위 20개와 코사인 유사도 후보 상위 20개를 동등한 가중치의 RRF로 합쳐 최대 10개 표시합니다. RRF는 각 목록의 순위에 `1/(60+순위)`를 부여해 더하는 방식입니다.
- 임베딩 후보의 최소 코사인 유사도는 임시로 0.35를 사용합니다. 최종 정책이 아니며 새 실행 방식의 결과를 보고 다시 검토해야 합니다. `--min-score 0.5` 등으로 바꿀 수 있습니다. 임계값과 관계없이 키워드 후보는 혼합 후보에 포함됩니다.
- 혼합 결과는 최신순이 아니라 결합한 점수순입니다. 임베딩 점수가 높더라도 관련 없는 기사가 나올 수 있고 결과가 10개보다 적을 수도 있습니다.

## 확인할 내용

터미널의 제목·링크와 `comparison_실행ID.txt` 보고서를 확인하세요. 보고서에는 검색어, 사용자, 모델 버전, 후보 수, 테스트 기준, 검색 시간과 두 결과가 저장됩니다.

1. `반도체`처럼 직접 등장하는 단어로 두 방식의 차이를 비교합니다.
2. `개인정보를 안전하게 지키는 기술`처럼 문장으로 검색해 단어 일치가 부족해도 의미가 관련된 기사를 찾는지 확인합니다.
3. 관련 기사로 판단한 결과 수와 순위, 관련 없는 결과를 각각 기록합니다. 결과가 더 많다는 사실만으로 더 좋은 검색이라고 판단하지 않습니다.
4. 사용자별 관심사 범위가 지켜지는지 확인합니다.

시간 값은 간단한 로컬 측정입니다. 모델 로드 시간은 `model_load_seconds`, 로드 후 검색어 인코딩 시간은 `query_embedding_seconds`로 구분하며 캐시·CPU 상태에 영향을 받습니다. 유사도·RRF 점수는 정확도 확률이 아닙니다. 이 비교를 확인한 뒤 웹 화면에 검색 방식 선택 기능을 연결할 수 있습니다.

공식 문서: [Sentence Transformers 설치](https://sbert.net/docs/installation.html), [모델 로드와 인코딩](https://sbert.net/docs/package_reference/sentence_transformer/model.html), [BAAI/bge-m3 모델](https://huggingface.co/BAAI/bge-m3).

모델 호출 없이 순위 결합·벡터 검증·색인 무효화 조건을 점검하려면 다음 명령을 실행하세요.

```cmd
python -m unittest discover -s ui_step4 -p test_compare.py
```
